### 39.5.3 把任务执行合并成统一 SSE 流

​        先打开 `api/app/application/react_agent_service.py`。

​        第 38 章以前，前端虽然能看到计划和工具调用，但流程仍然偏接口验证：

```Plain
旧教学验证流程：消息接口 -> 计划接口 -> 执行接口
```

​        这会带来两个问题：

​        展开来看，第一，前端需要知道太多后端步骤；第二，任务过程不是一条连续流，用户感觉不到 Agent 正在实时执行。这些点放在一起看，构成了本章叙述中需要连续理解的一条线索，而不是彼此孤立的项目清单。

​        所以本章新增 `stream_latest_plan()`：

```Python
# ===================== 第6步：以流式方式执行当前会话的最新计划 =====================
async def stream_latest_plan(self, session_id: UUID):
    """边执行计划边产出事件。"""

    # 1. 确认会话存在，并读取当前会话全部事件。
    session = await self.uow.sessions.get(session_id)
    if session is None:
        raise AppException(
            message="session not found",
            code=404,
            status_code=404,
        )

    # 2. 找到最新的 plan_created 事件。PlannerService 会先写入它。
    events = await self.uow.session_events.list_by_session(session_id)
    plan_event = self._find_latest_plan_event(events)
    plan = plan_event.payload

    # 3. 每执行一个步骤，就提交并 yield 对应事件。
    for index, step in enumerate(plan.get("steps", []), start=1):
        step_events = await self._execute_step(
            session_id=session_id,
            plan=plan,
            step=step,
            index=index,
        )
        await self.uow.commit()
        for event in step_events:
            yield event
```

#### 39.5.3.1 代码讲解

​        这个方法不一次性返回所有事件，而是边执行边 `yield`。

​        每个步骤会产生：

```Plain
step_started
tool_called
step_completed
```

​        全部完成后再产生：

```Plain
task_done
```

​        如果执行出错，则产生：

```Plain
task_error
```

​        这就是前端看到“任务过程正在流动”的基础。

### 39.5.4 改造`/messages/stream`

```Python
async def stream_message(
    session_id: UUID,
    payload: MessageCreateRequest,
    service: SessionService = Depends(build_session_service),
    planner_service: PlannerService = Depends(build_planner_service),
    react_service: ReActAgentService = Depends(build_react_agent_service),
) -> StreamingResponse:
    async def event_stream():
        # ===================== 第1步：会话进入 running，前端显示任务开始 =====================
        running_session = await service.mark_running(session_id)
        yield encode_sse("session_status", to_session_response(running_session).model_dump(mode="json"))

        # ===================== 第2步：写入用户消息，并推送 message_created =====================
        message, message_event = await service.create_user_message(
            session_id=session_id,
            content=payload.content,
        )
        yield encode_sse(message_event.type.value, to_event_response(message_event).model_dump(mode="json"))

        # ===================== 第3步：自动生成计划，并推送 plan_created =====================
        _plan, plan_event = await planner_service.create_plan(
            session_id=session_id,
            task=payload.content,
        )
        yield encode_sse(plan_event.type.value, to_event_response(plan_event).model_dump(mode="json"))

        # ===================== 第4步：流式执行计划，把步骤和工具事件逐个推给前端 =====================
```

### 39.5.5 前端只消费统一 SSE

```TypeScript
  if (eventName === "plan_created") {
    return 420;
  }
  if (eventName === "step_started") {
    return 520;
  }
  if (eventName === "tool_called") {
    return 680;
  }
  if (eventName === "step_completed") {
    return 420;
  }
  return 120;
}

sendMessage: async () => {
  const sessionId = get().selectedSessionId;
  const content = get().draft.trim();

  // ===================== 第1步：通过统一 SSE 发送任务并接收执行过程 =====================
  await streamMessage(sessionId, content, async (event) => {
    // 第39章先给前端展示加一点节奏。
    // 真实模型和工具调用通常会自然耗时；当前课程 demo 工具返回很快，
    // 如果不做节奏控制，用户会感觉所有内容瞬间出现，看不到“执行中”的过程。
    await sleep(getPresentationDelay(event.event));

    const sessionEvent = toSessionEventItem(event);
    if (!sessionEvent) {
      return;
    }
    set((state) => {
      const currentEvents = state.events.type === "ready" ? state.events.data : [];
      const events = [...currentEvents, sessionEvent];
      return {
        events: { type: "ready", data: events },
        latestPlan: applyExecutionEvents(getLatestPlan(events), events),
      };
    });
  });
}
```

#### 39.5.5.1 业务讲解

​        这里不是把计划能力删掉，而是把计划、步骤和工具执行变成后端统一输出的事件流。

​        用户看到的是：

```Plain
输入任务 -> 发送 -> 中间对话流自动出现计划、步骤、工具调用和结果
```

​        系统内部仍然会做：

```Plain
写入消息 -> 创建计划 -> 执行步骤 -> 记录工具事件 -> 推送 SSE
```

​        这样前端不用知道后端分了几个应用服务，只需要把事件按顺序渲染出来。

#### 39.5.5.2 为什么要加展示节奏

​        真实 Agent 调用 LLM、搜索、浏览器、Shell 或远程 Agent 时，本身就会有等待时间。

​        但课程当前很多工具还是 demo 实现，返回速度非常快。如果后端一口气把所有事件推完，前端虽然用了 SSE，视觉上也会像“一次性全部输出”。

​        所以本章在前端加入 `getPresentationDelay()`：

```Plain
message_created  -> 轻微停顿
plan_created     -> 等用户看到计划出现
step_started     -> 等用户看到步骤进入 running
tool_called      -> 等用户看到工具正在调用
step_completed   -> 等用户看到步骤完成
```

​        这不是伪造后端能力，而是让当前阶段的 UI 先具备真实 Agent 产品的表达能力。后续工具调用变慢、模型流式输出完善后，这里的延迟可以缩短或删除。

```TypeScript
function buildStepViews(plan: AgentPlan, events: SessionEventItem[]): StepView[] {
  return plan.steps.map((step) => {
    const related = events.filter((event) => getString(event.payload.step_id) === step.id);
    const started = related.find((event) => event.type === "step_started") ?? null;
    const completed = related.find((event) => event.type === "step_completed") ?? null;
    const toolEvent = related.find((event) => event.type === "tool_called") ?? null;

    const status = completed ? "completed" : started ? "running" : step.status;

    return {
      ...step,
      status,
      toolEvent,
      summary: getString(completed?.payload.summary),
    };
  });
}
```

### 39.6.1 代码讲解

​        `plan.steps` 是计划原始步骤。

​        `events` 是后端 SSE 推过来的执行事件。

​        `buildStepViews()` 做的是一次“前端视图合成”：

​        具体来说，第一，如果某个步骤已经收到 `step_started`，状态变成 `running`；第二，如果某个步骤已经收到 `step_completed`，状态变成 `completed`；第三，如果某个步骤收到 `tool_called`，步骤里就出现“查看工具详情”按钮；第四，如果完成事件里有 `summary`，就用它展示步骤结果。这些点放在一起看，构成了本章叙述中需要连续理解的一条线索，而不是彼此孤立的项目清单。

​        这样中间区域展示的不是零散事件，而是用户能看懂的执行过程。

## 39.9 关键理解

​        第 38 章做的是：


```Plain

右侧：当前选中对象的详情
弹层：大图、全文、长输出
```

## 39.11 常见问题

​        解释：确认执行的是 `browser_screenshot` 工具，并且工具输出里包含 `kind=browser_screenshot`。

- 问题：为什么还没有浏览器/VNC 大屏交互？

​        解释：本章先做工具结果和文件预览弹层。VNC 大屏会在后续工作台细化中继续增强。
