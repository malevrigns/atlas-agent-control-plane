# 第二十六章. AI 对话工作台与执行详情

## 26.1 合章说明

​        旧版教程把“AI 对话工作台再造”与“发送即执行与详情抽屉开阖”拆成了相邻两章。两者实际上属于同一条能力链：前者把基础结构立住，后者让它进入可用状态。本章将它们合并为前后两个阶段，保留原来的实现、验证与工程判断，同时减少能力尚未闭环时的章节跳转。

## 26.2 第一阶段：AI 对话工作台再造

### 26.2.1 本阶段目标

​        学完本阶段后，你将能够：

​        具体来说，第一，理解 AI Agent 产品里的“可观察执行轨迹”是什么；第二，区分可展示的执行过程和模型隐藏推理；第三，把用户消息、计划、步骤状态和工具调用合并成对话时间线；第四，在中间对话流里展示多 Agent 协作结果；第五，点击工具调用卡片后，让右侧工具预览自动切到对应工具；第六，删除旧的消息列表和事件记录演示组件。这些点放在一起看，构成了本阶段叙述中需要连续理解的一条线索，而不是彼此孤立的项目清单。

### 26.2.2 重要说明：这里不是展示隐藏思维链

​        真实产品里经常会看到：

```Plain
正在分析任务
正在生成计划
正在调用浏览器
正在查看工具结果
正在汇总答案
```

​        这些是“可观察执行轨迹”，不是模型内部隐藏 Chain-of-Thought。

​        本项目会展示：

​        换句话说，第一，用户消息；第二，AI 生成的计划；第三，步骤开始和完成状态；第四，工具调用参数和输出摘要；第五，多 Agent 的子任务、执行结果和评审状态；第六，任务完成或失败状态。这些点放在一起看，构成了本阶段叙述中需要连续理解的一条线索，而不是彼此孤立的项目清单。

​        本项目不会展示模型内部未公开的隐藏推理原文。

​        这一点很重要，因为产品需要让用户理解 Agent 在做什么，但不能把模型内部隐私推理直接暴露出来。

### 26.2.4 本阶段要解决的问题

​        第 25 章之前，页面中间主要展示消息，右侧展示计划、工具和事件。

​        问题是：用户真正关注的是一条完整对话里发生了什么。

​        如果把内容拆得太散：

```Plain
中间：只看消息
右侧：看计划
右侧另一个区域：看工具
右侧另一个区域：看事件
```

​        用户就很难建立因果关系：

```Plain
哪条消息触发了哪个计划？
哪个计划步骤调用了哪个工具？
哪个工具结果导致步骤完成？
多 Agent 协作结果在哪里？
```

​        本阶段把这些内容合并成中间的对话执行时间线。

​        右侧工具预览不再负责“告诉用户发生了什么”，而是负责“展示被选中工具的详细内容”。

#### 26.2.7.2 把消息和事件合成时间线

​        `ConversationTimeline` 的核心是把两类数据合在一起：

```Plain
session_messages
session_events
```

​        代码如下：

```TypeScript
function buildTimelineItems(
  messages: ChatMessage[],
  events: SessionEventItem[],
): TimelineItem[] {
  const visibleEvents = events.filter((event) =>
    [
      "plan_created",
      "step_started",
      "tool_called",
      "step_completed",
      "task_done",
      "task_error",
    ].includes(event.type),
  );

  return [
    ...messages.map((message) => ({
      kind: "message" as const,
      id: `message-${message.id}`,
      created_at: message.created_at,
      message,
    })),
    ...visibleEvents.map((event) => ({
      kind: "event" as const,
      id: `event-${event.id}`,
      created_at: event.created_at,
      event,
    })),
  ].sort((left, right) => left.created_at.localeCompare(right.created_at));
}
```

##### 26.2.7.2.1 代码讲解

​        这里没有展示 `message_created` 事件。

​        原因是用户消息已经在 `messages` 里展示了。如果同时展示 `message_created`，页面会重复出现一条“消息已创建”事件，用户体验会很啰嗦。

​        真正进入对话执行流的是这些事件：

​        具体来说，第一，`plan_created`：AI 生成计划；第二，`step_started`：某个步骤开始；第三，`tool_called`：某个工具被调用；第四，`step_completed`：某个步骤完成；第五，`task_done`：任务完成；第六，`task_error`：任务失败。这些点放在一起看，构成了本阶段叙述中需要连续理解的一条线索，而不是彼此孤立的项目清单。

```TypeScript
function getEventMeta(type: string) {
  if (type === "step_started") {
    return {
      className: "border-sky-200 bg-sky-50 text-sky-700",
      icon: CircleDot,
      label: "开始执行步骤",
      tone: "running" as const,
    };
  }
  if (type === "step_completed") {
    return {
      className: "border-emerald-200 bg-emerald-50 text-emerald-700",
      icon: CheckCircle2,
      label: "步骤完成",
      tone: "success" as const,
    };
  }
  if (type === "task_error") {
    return {
      className: "border-rose-200 bg-rose-50 text-rose-700",
      icon: AlertCircle,
      label: "执行失败",
      tone: "error" as const,
    };
  }
  return {
    className: "border-slate-200 bg-white text-slate-700",
    icon: MessageSquare,
    label: type === "task_done" ? "任务完成" : type,
    tone: "assistant" as const,
  };
}
```

```Python
# ===================== 第6步：以流式方式执行当前会话的最新计划 =====================
async def stream_latest_plan(self, session_id: UUID):
    """边执行计划边产出事件。"""

    # 1. 确认会话存在，并读取当前会话全部事件。
    session = await self.uow.sessions.get(session_id)
    if session is None:
        raise AppException(
            message="session not found",
            code=404,
            status_code=404,
        )

    # 2. 找到最新的 plan_created 事件。PlannerService 会先写入它。
    events = await self.uow.session_events.list_by_session(session_id)
    plan_event = self._find_latest_plan_event(events)
    plan = plan_event.payload

    # 3. 每执行一个步骤，就提交并 yield 对应事件。
    for index, step in enumerate(plan.get("steps", []), start=1):
        step_events = await self._execute_step(
            session_id=session_id,
            plan=plan,
            step=step,
            index=index,
        )
        await self.uow.commit()
        for event in step_events:
            yield event
```

##### 26.3.5.3.1 代码讲解

​        这个方法不一次性返回所有事件，而是边执行边 `yield`。

​        每个步骤会产生：

```Plain
step_started
tool_called
step_completed
```

​        全部完成后再产生：

```Plain
task_done
```

​        如果执行出错，则产生：

```Plain
task_error
```

​        这就是前端看到“任务过程正在流动”的基础。

```TypeScript
function buildStepViews(plan: AgentPlan, events: SessionEventItem[]): StepView[] {
  return plan.steps.map((step) => {
    const related = events.filter((event) => getString(event.payload.step_id) === step.id);
    const started = related.find((event) => event.type === "step_started") ?? null;
    const completed = related.find((event) => event.type === "step_completed") ?? null;
    const toolEvent = related.find((event) => event.type === "tool_called") ?? null;

    const status = completed ? "completed" : started ? "running" : step.status;

      status,

}
```

### 26.3.9 关键理解

​        本章第一阶段做的是：


​        本阶段做的是：

```Plain

右侧：当前选中对象的详情
弹层：大图、全文、长输出
```
