# 第四十四章. 项目简历落笔

## 44.1 本章目标

​        完成本章后，你会得到一份可以直接改写进简历、作品集或面试自我介绍里的 AI Agent 项目描述。

​        本章重点不是继续写功能，而是把前面 67 章完成的系统能力，整理成资深开发视角下更有说服力的项目表达。

​        你会获得：

​        具体来说，第一，一版完整的 STAR 风格项目描述；第二，一版适合简历项目经历区的压缩版；第三，一版适合面试口述的介绍话术；第四，一组可写进简历的技术关键词；第五，一组面试追问时可以展开的亮点。这些点放在一起看，构成了本章叙述中需要连续理解的一条线索，而不是彼此孤立的项目清单。

## 44.2 为什么需要这一章

​        技术项目最终不只是“做完”。

​        如果你想把它放进简历、作品集或面试展示里，还需要回答：

​        换句话说，第一，这个项目到底是什么？；第二，你在里面承担什么角色？；第三，你解决了哪些复杂问题？；第四，项目和普通 Demo 有什么区别？；第五，技术深度体现在哪里？；第六，最终结果如何证明？。这些点放在一起看，构成了本章叙述中需要连续理解的一条线索，而不是彼此孤立的项目清单。

​        很多项目明明做得不差，但简历上只写成：

```Plain
使用 FastAPI + Next.js 开发了一个 AI Agent 系统。
```

​        这句话太弱。

​        它没有体现：

​        从实现顺序看，第一，系统复杂度；第二，架构设计能力；第三，Agent 执行链路；第四，工具系统；第五，沙箱隔离；第六，前端产品化；第七，工程交付能力。这些点放在一起看，构成了本章叙述中需要连续理解的一条线索，而不是彼此孤立的项目清单。

​        所以本章会把课程里的 AtlasAgent，转换成更适合正式简历的业务化项目表达。

​        这里要注意一个细节：

```Plain
课程项目名：AtlasAgent
简历项目名：不要直接写 AtlasAgent
```

​        `AtlasAgent` 更像课程代号或个人项目名。正式简历里，如果你想让项目看起来更像公司内部真实项目，建议使用更业务化的名称，例如：

​        放到工程语境里看，第一，智能任务执行平台；第二，企业级 AI Agent 工作台；第三，多 Agent 自动化协作平台；第四，AI 办公任务执行系统；第五，智能研发/运营助理平台。这些点放在一起看，构成了本章叙述中需要连续理解的一条线索，而不是彼此孤立的项目清单。

​        下面的简历示例会默认使用“智能任务执行平台”这类表达，而不是直接使用课程代号。

## 44.3 完整项目描述

### 44.3.1 智能任务执行平台 / 全栈 AI Agent 工作台

**角色**

​        ❀ 智能任务执行平台的架构设计者与核心开发者

​        ❀ 负责后端 Agent 执行链路、工具系统、沙箱能力、前端工作台和 Docker 私有化部署方案设计与落地

**行动**

​        ❀ 设计并实现完整 Agent 执行链路：基于 Planner + ReAct + TaskRunner 构建任务规划、步骤执行、工具调用、失败恢复和最终总结闭环

​        ❀ 搭建多工具调用体系：封装 SearchTool、FileTool、ShellTool、BrowserTool，并统一抽象工具 schema、调用参数、执行结果和事件流展示

​        ❀ 实现沙箱执行环境：基于独立 Sandbox 服务隔离文件读写、Shell 命令、Playwright 浏览器自动化和 VNC 远程桌面，降低高风险操作对主服务的影响

​        ❀ 建设实时任务体验：使用 SSE / Redis Stream 推送 Agent 执行事件，前端实现任务理解、计划步骤、工具调用、最终回答的流式展示

​        ❀ 完成文件理解能力：支持文件上传、解析、摘要、引用片段和预览，让 Agent 能基于 Markdown、代码、CSV、PDF 等文件完成分析任务

​        ❀ 接入外部 Agent 能力：实现 MCP 工具接入、A2A 远程 Agent 调用和多 Agent 协作编排，支持 Manager / Worker / Reviewer 模式

​        ❀ 设计长期记忆与上下文工程：实现会话上下文压缩、长期记忆存储、记忆检索和上下文注入，提升多轮任务执行稳定性

​        ❀ 打磨前端 Agent 工作台：实现会话列表、对话执行流、步骤时间线、工具详情抽屉、文件预览、浏览器截图和配置中心

​        ❀ 完成工程化交付：基于 FastAPI、Next.js、PostgreSQL、Redis、Nginx、Docker Compose 构建可本地运行、可私有化部署的完整系统

**遇到的挑战**

​        ❀ Agent 执行链路复杂，涉及 LLM、工具、沙箱、数据库、Redis、前端事件流等多个模块，需要保证任务状态、事件顺序和失败恢复一致

​        ❀ 工具调用结果类型差异较大，搜索、文件、Shell、浏览器、MCP、A2A 的输出结构不同，需要设计统一事件模型和前端展示协议

​        ❀ 浏览器自动化和 Shell 执行存在安全风险，通过独立 Sandbox、Nginx 网关、运行时配置和安全检查机制降低主系统风险

​        ❀ 前端不能只做接口演示，需要对齐成熟 Agent 产品体验，将任务过程、工具调用和最终回答组织成可理解、可观察的对话流

**结果**

​        ❀ 完成一个可运行、可演示、可部署的全栈 AI Agent 项目，覆盖对话、规划、工具调用、浏览器自动化、文件理解、多 Agent 和记忆系统

​        ❀ 支持用户通过自然语言发起任务，系统自动完成规划、执行、工具调用、结果引用和最终总结输出

​        ❀ 前端工作台具备成熟 Agent 产品形态，可展示步骤执行、工具详情、浏览器截图、文件引用和最终交付结果

​        ❀ 项目具备 Docker Compose 一键启动和私有化部署能力，可作为企业级 AI Agent 项目原型或简历展示项目

​        ❀ 沉淀 60+ 章节工程化教程，覆盖从项目初始化、DDD 分层、Agent Loop、Tool System、MCP/A2A 到部署验收的完整实践路径

## 44.10 不建议这样写

​        不要只写：

```Plain
使用 FastAPI 和 Next.js 开发了一个 AI Agent 项目。
```

​        这句话太泛。

​        也不要写成：

```Plain
实现了一个 AI Agent Demo。
```

​        这句话没有技术细节，也容易让面试官觉得项目只是简单演示。

​        更好的表达方式是：

```Plain
实现了包含任务规划、ReAct 执行、工具调用、沙箱隔离、浏览器自动化、多 Agent 协作、长期记忆和 Docker 私有化部署的全栈 AI Agent 工作台。
```

​        这句话能直接体现复杂度和工程含量。
