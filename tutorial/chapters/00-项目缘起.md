# 第 0 章. 项目缘起

​        在写第一行代码之前，笔者希望先把项目的样子说明白。AtlasAgent 最终会长成一个 AI Agent 工作台：左侧是会话列表，中间是用户和 Agent 的对话流，右侧是工具详情、文件预览、浏览器观察和执行状态。用户输入一个任务后，系统不是简单把问题丢给模型，而是先生成计划，再按步骤执行。执行过程中，后端会持续把事件通过 SSE 推给前端，前端则把这些事件渲染成用户能理解的执行流。
​        普通 ChatBot 的流程大多是“用户输入 -> 模型回答”。AtlasAgent 的流程更像“用户输入 -> 任务规划 -> 上下文构建 -> 工具选择 -> 工具执行 -> 观察结果 -> 继续推理 -> 最终回答”。这两者的差别非常关键。前者是问答，后者是执行。笔者认为，真正值得写进简历和作品集的 Agent 项目，必须能展示这个执行链路，而不是只展示一个聊天框。
​        这个项目最终应该具备几个可演示能力：上传文件后能解析和引用，搜索资料后能总结来源，调用浏览器后能观察页面，调用 Shell 后能展示 stdout、stderr 和退出码，执行失败后能呈现错误状态，任务结束后能生成带证据的最终回答。换句话说，我们不是在做一个“看起来像 AI 产品”的页面，而是在做一个能被追问、能被验证、能被部署的工程系统。
