## 37.4 重要边界：为什么不直接改 YAML 和密钥

​        本章不会让浏览器直接改写：

```Plain
api/config/llm.yaml
api/config/mcp.yaml
api/config/a2a.yaml
.env
```

​        原因有三个：

​        展开来看，第一，密钥不能从浏览器表单写入仓库文件；第二，YAML 写入需要更完整的校验、备份和回滚；第三，当前阶段更重要的是先稳定设置页的数据协议和交互结构。这些点放在一起看，构成了本章叙述中需要连续理解的一条线索，而不是彼此孤立的项目清单。

​        所以本章采用：

```Plain
YAML / 环境变量  ->  后端读取  ->  设置聚合接口  ->  前端设置页
前端新增/删除     ->  后端进程内运行时状态
```

​        这意味着新增的“运行时集成”重启 API 后会消失。

​        后续生产化设置章节会继续实现：

​        具体来说，第一，配置持久化；第二，密钥管理；第三，配置校验；第四，配置热更新；第五，操作审计。这些点放在一起看，构成了本章叙述中需要连续理解的一条线索，而不是彼此孤立的项目清单。

### 37.6.1 定义设置接口 Schema

​        创建 `api/app/schemas/app_settings.py`：

```Python
from typing import Literal

from pydantic import BaseModel, Field


SettingsIntegrationKind = Literal["llm", "mcp", "a2a", "multi_agent"]


class SettingsItemResponse(BaseModel):
    name: str  # 配置项名称，例如 provider name、MCP server name 或 Agent key。
    description: str  # 配置项说明，前端设置页直接展示。
    enabled: bool  # 当前配置项是否可用。
    metadata: dict[str, object]  # 额外信息，例如 transport、url、api_key_env。


class SettingsModuleResponse(BaseModel):
    key: str  # 模块稳定标识，例如 llm、mcp、a2a、multi_agent。
    name: str  # 展示名称。
    description: str  # 模块作用说明。
    enabled: bool  # 设置页中的运行时启用状态。
    default_item: str | None  # 当前默认项，例如默认 provider 或默认远程 Agent。
    items: list[SettingsItemResponse]  # 模块下的配置项列表。


class SettingsIntegrationResponse(BaseModel):
    id: str  # 运行时集成记录 ID。
    kind: SettingsIntegrationKind  # 集成类型。
    name: str  # 集成名称。
    description: str  # 集成说明。
    endpoint: str | None  # 外部服务地址，某些集成可以为空。
    enabled: bool  # 当前记录是否启用。


class AppSettingsResponse(BaseModel):
    modules: list[SettingsModuleResponse]
    integrations: list[SettingsIntegrationResponse]


class SettingsModuleUpdateRequest(BaseModel):
    enabled: bool | None = None
    default_item: str | None = Field(default=None, max_length=120)


class SettingsIntegrationCreateRequest(BaseModel):
    kind: SettingsIntegrationKind
    name: str = Field(min_length=1, max_length=120)
    description: str = Field(default="", max_length=500)
    endpoint: str | None = Field(default=None, max_length=500)
```

#### 37.6.1.1 代码讲解

​        这里把设置页数据拆成三层：

```Plain
AppSettingsResponse
  |
  +-- modules       LLM/MCP/A2A/多 Agent 模块
  |
  +-- integrations  用户新增的运行时集成记录
```

​        `metadata` 使用 `dict[str, object]`，因为不同配置项的补充信息不同：

​        换句话说，第一，LLM 需要展示 `api_key_env` 和 `configured`；第二，MCP 需要展示 `transport`；第三，A2A 需要展示 `url` 和 `version`；第四，多 Agent 需要展示角色 `capability`。这些点放在一起看，构成了本章叙述中需要连续理解的一条线索，而不是彼此孤立的项目清单。

​        服务入口：

```Python
class AppSettingsService:
    """聚合 LLM、MCP、A2A 和多 Agent 的设置页数据。

    当前版本不直接改写 YAML 配置文件，也不从接口接收真实密钥。
    浏览器中的操作会写入进程内状态，用来先打通设置页交互和接口协议。
    """

    def __init__(
        self,
        llm_service: LLMService | None = None,
        mcp_service: McpService | None = None,
        a2a_service: A2aService | None = None,
        multi_agent_service: MultiAgentService | None = None,
    ) -> None:
        # ===================== 第1步：保存各模块服务 =====================
        # 这些服务负责读取各自已有配置；设置服务只做聚合和运行时开关。
        self.llm_service = llm_service or LLMService()
        self.mcp_service = mcp_service or McpService()
        self.a2a_service = a2a_service or A2aService()
        self.multi_agent_service = multi_agent_service or MultiAgentService()

        # ===================== 第2步：保存运行时覆盖状态 =====================
        # module_overrides 只影响设置页展示，避免把临时操作写坏 YAML。
        self.module_overrides: dict[str, dict[str, object]] = {}
        self.integrations: dict[str, SettingsIntegration] = {}
```

​        读取完整快照：

```Python
def get_snapshot(self) -> AppSettingsSnapshot:
    """返回设置页需要展示的完整快照。"""

    modules = [
        self._build_llm_module(),
        self._build_mcp_module(),
        self._build_a2a_module(),
        self._build_multi_agent_module(),
    ]
    return AppSettingsSnapshot(
        modules=[self._apply_override(module) for module in modules],
        integrations=list(self.integrations.values()),
    )
```

## 37.7 关键理解

​        本章最重要的是理解“设置展示”和“配置持久化”的区别。

​        当前实现：

```Plain
展示已有配置：来自 YAML 和环境变量
模块开关：进程内运行时覆盖
新增集成：进程内运行时记录
```

​        后续生产化实现：

```Plain
展示已有配置：来自数据库或配置中心
模块开关：持久化到数据库
新增集成：写入配置表
密钥：写入密钥管理系统
```

​        先做运行时设置是为了让交互、接口和页面结构先稳定。

​        放到工程语境里看，第一，点击左侧“设置”；第二，确认主区域出现 LLM、MCP、A2A、多 Agent 模块；第三，点击任意模块的启用开关；第四，新增一条 MCP 或 A2A 集成；第五，删除刚才新增的集成；第六，点击左侧“工作台”，确认对话区仍然正常。这些点放在一起看，构成了本章叙述中需要连续理解的一条线索，而不是彼此孤立的项目清单。

## 37.9 最终实现修订：配置必须真实生效

第一版设置页的 `module_overrides` 只改变 API 进程内的展示数据，重启即丢失，也不会阻止工具继续运行。交付版新增 `ModulePolicyStore`，把模块状态原子写入运行时配置文件，并在真正的执行入口再次检查：

- `llm=false` 时，`LLMService.chat()` 拒绝发起模型请求；
- `mcp`、`a2a`、`sandbox` 等模块关闭时，`ToolRuntime` 在调用前拒绝对应工具；
- 设置页重启后从持久化策略重建状态，不依赖进程内字典；
- 删除 LLM、MCP 或 A2A 集成时同步修改对应 YAML，重启后不会“复活”。

配置文件采用“写临时文件 → `fsync` → 原子替换”的方式更新，避免进程崩溃留下半截 YAML。生产环境还应把运行时配置目录挂载到持久卷，并限制只有 API 服务账号可写。

密钥与普通配置必须分开。设置页只保存环境变量名，例如：

```yaml
providers:
  openai:
    api_key_env: OPENAI_API_KEY
```

真实密钥只从环境变量或密钥管理服务读取，接口响应不会返回密钥，页面也不能回显。对可产生进程或外部网络连接的配置，还要先通过运维侧 allowlist：MCP stdio 命令、MCP HTTP 地址和 A2A 地址不在允许范围内时，配置不能启用。

验证时不要只看开关动画，应完成以下闭环：切换模块、重启 API、重新读取配置、尝试执行被禁用工具；新增再删除一个集成、重启 API、确认它没有恢复；最后检查接口和浏览器页面都没有出现真实密钥。

## 37.10 常见问题

- 问题：设置页切换开关后，重启 API 又恢复了怎么办？

​        解释：交付版会把模块状态原子写入运行时配置。若重启后仍恢复，检查运行时配置目录是否可写、是否被 Docker 持久挂载，并查看 API 日志中的写入错误。

- 问题：为什么设置页不允许输入真实 API Key？

​        解释：密钥应该放在环境变量或密钥管理系统中，不能通过普通前端表单写入仓库文件。

- 问题：新增集成后为什么工具列表没有立刻多一个真实工具？

​        解释：交付版会写入真实 MCP/A2A 配置，但只有通过运维 allowlist 且成功发现工具后，工具列表才会变化。先检查配置是否启用、地址或命令是否获准，再查看发现错误。

- 问题：`/api/config/app` 返回 500 怎么办？

​        解释：优先检查 `api/config/llm.yaml`、`api/config/mcp.yaml`、`api/config/a2a.yaml` 是否存在，并确认 Docker 容器里已挂载最新代码。
