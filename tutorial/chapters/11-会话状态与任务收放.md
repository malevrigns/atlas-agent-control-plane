# 第十一章. 会话状态与任务收放

## 11.1 本章目标
​        第 10 章让事件可以流式推送，但会话本身还缺少任务控制感。用户看到事件在动，却不知道当前会话到底是空闲、运行中，还是已经被停止；事件来了之后，也没有一个清晰的位置告诉用户是否有未读内容。本章要补齐这层会话状态。
​        本章不新增数据库表，而是使用第 07 章已经预留的 `sessions.status` 和 `sessions.unread_count`。读者会编写停止会话接口、清除未读数接口，在 SSE 流里推送会话状态变化，并在前端增加会话控制栏。zustand store 也会继续承担状态协调职责，统一管理停止、清未读、运行中状态和会话列表更新。

## 11.2 最终效果
​        本章结束后，聊天工作区顶部会出现会话控制栏。
​        控制栏会展示：

```Plain
当前会话标题
状态：idle / running / stopped
未读数量
清未读按钮
停止按钮
```

​        发送消息时，SSE 流会推送状态变化：

```Plain
session_status: running
message_created
session_status: idle
stream_done
```

​        新增后端接口：

```Plain
POST /api/sessions/{session_id}/stop
POST /api/sessions/{session_id}/read
```

## 11.3 本章要解决的问题
​        第 10 章已经完成 SSE 流式事件，但会话仍然缺少任务控制感。
​        真实的 Agent 会话通常需要知道：

```Plain
当前是否正在运行
能不能停止
有没有未读事件
用户是否已经查看过最新事件
```

​        第 07 章创建 `sessions` 表时，已经预留了两个字段：

```Plain
status
unread_count
```

​        所以本章不新增数据库迁移，而是复用这两个字段，把它们接入后端接口和前端界面。
​        本章完成后，请求链路变成：

```Plain
发送消息
  |
  v
会话状态变成 running
  |
  v
写入消息和事件
  |
  v
未读数 +1
  |
  v
会话状态变回 idle
  |
  v
前端展示状态和未读数
```

### 11.6.1 扩展 SessionRepository 协议


#### 11.6.1.1 这段代码的业务流程
​        这三个方法分别服务三个业务动作：

```Plain
发送消息 -> update_status(running) -> update_status(idle)
产生新事件 -> increment_unread()
用户查看后 -> clear_unread()
```

#### 11.6.1.2 为什么这样设计
​        Repository 协议先定义能力，基础设施层再实现。
​        这样应用服务只依赖抽象，不关心底层是不是 SQLAlchemy。

### 11.6.2 实现状态和未读数更新
​        打开 `api/app/infrastructure/repositories/session_repository.py`，在 `SqlAlchemySessionRepository` 中新增：

```Python
async def update_status(self, session_id: UUID, status: str) -> Session | None:
    stmt = self._active_stmt().where(SessionModel.id == session_id)
    result = await self.db_session.execute(stmt)
    model = result.scalar_one_or_none()
    if model is None:
        return None
    model.status = status
    model.updated_at = datetime.now(UTC)
    await self.db_session.flush()
    await self.db_session.refresh(model)
    return model.to_entity()

async def increment_unread(self, session_id: UUID) -> None:
    stmt = self._active_stmt().where(SessionModel.id == session_id)
    result = await self.db_session.execute(stmt)
    model = result.scalar_one_or_none()
    if model is not None:
        model.unread_count += 1
        model.updated_at = datetime.now(UTC)

async def clear_unread(self, session_id: UUID) -> Session | None:
    stmt = self._active_stmt().where(SessionModel.id == session_id)
    result = await self.db_session.execute(stmt)
    model = result.scalar_one_or_none()
    if model is None:
        return None
    model.unread_count = 0
    model.updated_at = datetime.now(UTC)
    await self.db_session.flush()
    await self.db_session.refresh(model)
    return model.to_entity()
```

#### 11.6.2.1 这段代码的业务流程
​        这三个方法都先查活跃会话：

```Python
self._active_stmt().where(SessionModel.id == session_id)
```

​        这样已经软删除的会话不会被修改。
​        `update_status()` 和 `clear_unread()` 返回最新实体，因为前端需要立刻用最新状态更新列表。
​        `increment_unread()` 不返回实体，因为它只在发送消息事务过程中使用，最终状态会通过后续刷新或 SSE 状态事件同步。

```Python
async def mark_running(self, session_id: UUID) -> Session:
    await self.get_session(session_id)
    session = await self.uow.sessions.update_status(
        session_id=session_id,
        status=SessionStatus.running.value,
    )
    await self.uow.commit()
    if session is None:
        raise AppException(
            message="session not found",
            code=404,
            status_code=404,
        )
    return session

async def mark_idle(self, session_id: UUID) -> Session:
    await self.get_session(session_id)
    session = await self.uow.sessions.update_status(
        session_id=session_id,
        status=SessionStatus.idle.value,
    )
    await self.uow.commit()
    if session is None:
        raise AppException(
            message="session not found",
            code=404,
            status_code=404,
        )
    return session

async def stop_session(self, session_id: UUID) -> Session:
    await self.get_session(session_id)
    session = await self.uow.sessions.update_status(
        session_id=session_id,
        status=SessionStatus.stopped.value,
    )
    await self.uow.commit()
    if session is None:
        raise AppException(
            message="session not found",
            code=404,
            status_code=404,
        )
    return session

async def clear_unread(self, session_id: UUID) -> Session:
    await self.get_session(session_id)
    session = await self.uow.sessions.clear_unread(session_id)
    await self.uow.commit()
    if session is None:
        raise AppException(
            message="session not found",
            code=404,
            status_code=404,
        )
    return session
```

#### 11.6.3.1 这段代码的业务流程
​        应用服务把 Repository 的底层操作组织成业务动作：

```Plain
mark_running -> 会话进入运行中
mark_idle    -> 会话回到空闲
stop_session -> 用户请求停止
clear_unread -> 用户已查看事件
```

#### 11.6.3.2 为什么这样设计
​        路由层不应该直接改数据库字段。
​        状态变化属于业务行为，放在 `SessionService` 中更清晰。后续接入任务队列时，也是在这里扩展取消任务、写停止事件等逻辑。

​        停止逻辑：

```TypeScript
stopSession: async () => {
  const sessionId = get().selectedSessionId;
  if (!sessionId) {
    set({ actionError: "请先选择一个会话" });
    return;
  }

  set({ actionError: null, stoppingSession: true });
  try {
    const session = await stopSession(sessionId);
    set((state) => ({
      sessions:
        state.sessions.type === "ready"
          ? {
              type: "ready",
              data: updateSession(state.sessions.data, session),
            }
          : state.sessions,
    }));
  } catch (error) {
    set({ actionError: getErrorMessage(error) });
  } finally {
    set({ stoppingSession: false });
  }
}
```

### 11.6.7 新增会话控制栏组件
​        创建 `ui/app/components/session-control-bar.tsx`：

```TypeScript
import { BellOff, Square } from "lucide-react";

import type { SessionItem } from "../types";

type SessionControlBarProps = {
  clearingUnread: boolean;
  onClearUnread: () => void;
  onStop: () => void;
  selectedSession: SessionItem | null;
  stopping: boolean;
};

export function SessionControlBar({
  clearingUnread,
  onClearUnread,
  onStop,
  selectedSession,
  stopping,
}: SessionControlBarProps) {
  const isRunning = selectedSession?.status === "running";
  const hasUnread = Boolean(selectedSession && selectedSession.unread_count > 0);

  return (
    <div className="flex items-center justify-between border-b border-slate-200 bg-white px-4 py-3 max-sm:flex-col max-sm:items-start max-sm:gap-3">
      <div>
        <div className="text-sm font-medium text-slate-900">
          {selectedSession ? selectedSession.title : "未选择会话"}
        </div>
        <div className="mt-1 text-xs text-slate-500">
          状态：{selectedSession?.status ?? "-"} · 未读：
          {selectedSession?.unread_count ?? 0}
        </div>
      </div>

      <div className="flex gap-2">
        <button
          className="flex h-9 items-center gap-2 rounded-md border border-slate-200 px-3 text-sm text-slate-600 transition hover:bg-slate-50 disabled:cursor-not-allowed disabled:text-slate-300"
          disabled={!selectedSession || !hasUnread || clearingUnread}
          onClick={onClearUnread}
          type="button"
        >
          <BellOff size={15} aria-hidden="true" />
          清未读
        </button>
        <button
          className="flex h-9 items-center gap-2 rounded-md border border-rose-200 px-3 text-sm text-rose-600 transition hover:bg-rose-50 disabled:cursor-not-allowed disabled:text-rose-300"
          disabled={!selectedSession || !isRunning || stopping}
          onClick={onStop}
          type="button"
        >
          <Square size={14} aria-hidden="true" />
          停止
        </button>
      </div>
    </div>
  );
}
```

#### 11.6.7.1 这段代码的业务流程
​        控制栏只接收 props，不直接请求接口。

```Plain
selectedSession -> 展示状态和未读数
onStop          -> 点击停止
onClearUnread   -> 点击清未读
```

​        按钮禁用规则：

```Plain
没有选中会话 -> 两个按钮都禁用
未读数为 0    -> 清未读禁用
状态不是 running -> 停止禁用
```

```TypeScript
        <h2 className="text-base font-semibold text-slate-950">事件记录</h2>
        <p className="mt-1 text-sm text-slate-500">
          本章先展示消息创建事件
        </p>
        <div className="mt-4">
```

## 11.7 关键理解
​        本章的停止能力是任务控制的第一步。
​        当前还没有后台任务队列，所以停止接口先做这件事：

```Plain
status = stopped
```

​        等后续加入任务队列后，停止接口会继续扩展：

```Plain
查找正在运行的任务
  |
  v
发送取消信号
  |
  v
写入停止事件
  |
  v
更新状态
```

​        未读数也是一样。
​        本章先把未读数作为会话级事件计数。后续如果有用户系统，可以再扩展成“某个用户对某个会话的未读状态”。

## 11.8 技术难点与亮点
​        技术难点：
​        本章的技术难点，是状态更新要和列表、详情、控制栏保持一致。SSE 中的 `session_status` 事件既要更新事件面板，也要更新会话列表。停止接口当前只是状态控制，后续还需要和真实任务取消衔接，所以文档中要明确它现在的边界。
​        项目亮点：
​        本章的项目亮点，是会话开始具备任务控制入口。前端控制栏被独立组件化，不污染聊天区域和页面入口；后端复用已有数据库字段，没有为了短期功能增加不必要迁移；第 12 章以后也可以继续接入后台任务和真实取消逻辑。

## 11.9 面试考点
​        面试里可以围绕这些问题展开：为什么会话需要 `idle`、`running`、`stopped` 这些状态，停止接口为什么不应该只在前端改状态，未读数为什么要放在后端维护，当前停止接口和真正后台任务取消有什么区别，前端为什么要用 store 统一更新会话列表，而不是每个组件自己维护状态。

## 11.11 常见问题

### 11.11.1 页面没有看到控制栏怎么办
​        第 11 章修改了前端组件和页面组合方式，如果浏览器里仍然是旧界面，通常不是接口问题，而是 UI 镜像还没有重新构建。此时需要执行 `docker compose build ui`，再重新启动服务，让新的 `SessionControlBar` 进入页面。

### 11.11.2 停止按钮一直不可点怎么办
​        停止按钮只在会话状态为 `running` 时可用。由于本章的 SSE 流还只是模拟一段很短的运行过程，状态从 `running` 回到 `idle` 的时间很短，所以按钮可能只会短暂进入可点击状态。这里要观察的是状态事件是否进入前端，而不是把它理解成完整的后台任务取消能力。

### 11.11.3 未读数为什么发送自己的消息也会增加
​        当前阶段还没有用户体系，未读数被当作会话事件计数使用。也就是说，只要会话产生了新消息和新事件，就会推动 `unread_count` 变化，用来演示从后端计数到前端清除的完整链路。后续接入用户系统后，这个字段才适合继续拆成“某个用户是否已读”的更细粒度状态。

### 11.11.4 停止接口为什么没有真正中断 SSE
​        本章还没有引入后台任务队列，也没有真正的 Agent Runner 长任务。`stop` 接口先把“停止”这个用户动作落到会话状态上，让前端和后端都具备统一的控制入口。等任务队列和运行器接入之后，这个入口会继续向下连接到具体任务的取消逻辑。

## 11.12 本章小结
​        本章完成了会话状态与任务控制的基础闭环。后端支持更新会话状态、停止会话和清除未读数，SSE 流开始推送 `session_status` 事件；前端新增会话控制栏，store 统一管理停止、清未读和流式状态更新。到这里，会话已经不只是消息容器，而开始具备任务运行状态，后续的任务队列、Agent Runner 和真正的取消能力都会沿着这条控制链路继续展开。
