# 第六章. 会话开立与左侧列表

表有了，还没有人往里面写。这一章让用户点「新工作区」，左侧出现一条会话，点它能进来。听起来像 CRUD 练习，真正要小心的是路径和工作区：用户会把 `D:\projects\demo` 贴进来，也会有人写 `../etc`。

代码在 `SessionService`。创建时标题空着就叫「新工作区」。`workspace_dir` 会先被拧成沙箱相对路径：盘符去掉，反斜杠换成正斜杠，`..` 直接拒绝。

![抽屉：每一格是一次工作](../assets/ch06-list.jpg)

```ts
async createSession(title: string, workspaceDir = "", fullAccess = false) {
  const id = newId();
  const stamp = nowIso();
  const row = {
    id,
    title: title.trim() || "新工作区",
    status: "idle",
    unreadCount: 0,
    workspaceDir: safeWorkspace(workspaceDir),
    fullAccess,
    createdAt: stamp,
    updatedAt: stamp,
    deletedAt: null,
  };
  await this.db.insert(sessions).values(row);
  return this.mapSession(row);
}
```

列表按 `updated_at` 倒序，并且 `deleted_at IS NULL`。删除是 UPDATE 打时间戳，不是 DELETE FROM。路由上 `DELETE /api/sessions/:id` 返回 204，身体为空——前端的 `requestApi` 对 204 有专门分支。

前端左侧 `SessionList` 读的是 zustand 里的 `sessions`。创建成功后不要只 `set({ selectedSessionId })`，要走 `selectSession`，把旧会话的消息、事件、附件清掉，否则你会看见新 ID 配着上一份时间线。这一点第 3 章优化时修过一次，写这一章的人很容易再踩。

工作区路径进沙箱时，空字符串表示挂载根；`full_access` 为真才允许走出工作区子目录。API 只存这两个字段，真正的路径监狱在 `backend/sandbox-ts` 的 `FileService.root()`。控制平面不要自己拼绝对路径。

试一下：

```bash
curl -X POST http://127.0.0.1:8000/api/sessions \
  -H "Content-Type: application/json" \
  -d "{\"title\":\"演示\",\"workspace_dir\":\"D:\\\\work\\\\atlas\"}"
curl http://127.0.0.1:8000/api/sessions
```

第一条的 `workspace_dir` 应变成 `work/atlas`。再 POST 一个 `"workspace_dir":".."` 应是 400。
