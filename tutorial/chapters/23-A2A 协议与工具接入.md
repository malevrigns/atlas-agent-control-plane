# 第二十三章. A2A 协议与工具接入

## 23.1 合章说明

​        旧版教程把“A2A 协议初识”与“A2A 工具入列”拆成了相邻两章。两者实际上属于同一条能力链：前者把基础结构立住，后者让它进入可用状态。本章将它们合并为前后两个阶段，保留原来的实现、验证与工程判断，同时减少能力尚未闭环时的章节跳转。

## 23.2 第一阶段：A2A 协议初识

### 23.2.1 本阶段目标
​        第 21 章讲的是 MCP。MCP 让一个 AI 应用能够发现和调用外部工具、资源和提示词，它解决的是“Agent 如何使用工具”的问题。可是当系统继续成熟以后，还会出现另一类需求：一个 Agent 不只是调用工具，而是把一部分任务交给另一个 Agent 协作完成。这个方向就是 A2A，也就是 Agent-to-Agent。
​        本阶段的目标，是先用确定性接口讲清 A2A 的基本角色和协作流程。我们不会在这一阶段真实调用远程 Agent，也不会处理远程认证、长任务轮询、artifact 下载和复杂状态同步。本阶段只做入门：定义 A2A 的领域对象，写一个 `A2aIntroService`，暴露 `/api/a2a/concepts`、`/api/a2a/demo/agent-card` 和 `/api/a2a/demo/message` 三个接口，并在前端右侧环境区展示 A2A 入门面板。
​        学完本阶段后，你应该能区分 Host Agent、Remote Agent、Agent Card 和 Task，理解 A2A 和 MCP 的差异，也能看懂一次模拟 `message/send` 为什么要先读取 Agent Card，再选择 Remote Agent，最后把任务消息发给远程 Agent。本章第二阶段会把远程 Agent 注册成工具，本阶段先把协议心智模型建立起来。

### 23.2.2 最终效果
​        本阶段结束后，后端会新增三组 A2A 入门接口：

```Plain
GET  /api/a2a/concepts
GET  /api/a2a/demo/agent-card
POST /api/a2a/demo/message
```

​        概念接口会返回 Host Agent、Remote Agent、Agent Card 和 Task 的职责说明。Agent Card 接口会返回一个课程内置的示例远程 Agent，它叫 `ResearchAssistantAgent`，能力包括 `research_brief` 和 `source_outline`。消息接口会模拟一次 Host Agent 向这个远程 Agent 发送任务，并返回 task id、状态、输入消息、输出消息和执行步骤。
​        命令行调用可以这样验证：

```Bash
curl http://localhost:8088/api/a2a/concepts
curl http://localhost:8088/api/a2a/demo/agent-card
curl -X POST http://localhost:8088/api/a2a/demo/message \
  -H "Content-Type: application/json" \
  -d '{"message":"请远程研究 Agent 帮我整理 A2A 协议要点"}'
```

​        前端方面，工具预览面板的“环境”页签会新增 `A2A Agent` 面板。这个面板会展示 A2A 核心角色、下一步说明和示例 Agent Card。它目前不展示真实远程调用结果，因为本阶段还没有把 A2A 接进工具事件流；本章第二阶段以后，远程 Agent 调用才会像 MCP 工具一样进入 AgentTool 和 `tool_called`。

### 23.2.3 本阶段要解决的问题
​        MCP 和 A2A 很容易被混在一起理解。MCP 关注的是 Host 如何使用外部工具，例如文件系统、浏览器、搜索、数据库或业务系统。A2A 关注的是一个 Agent 如何和另一个 Agent 协作。例如主 Agent 负责整体规划，研究 Agent 负责查资料，代码 Agent 负责改代码，评审 Agent 负责检查结果。它们都属于外部能力接入，但抽象层级不同。
​        如果没有 A2A，复杂任务会全部压在一个 Agent 身上。这个 Agent 既要规划，又要调研，又要写代码，还要评审。短任务还能接受，长任务就会出现上下文拥挤、角色混乱和执行边界不清的问题。A2A 的价值，是让 Host Agent 可以识别远程 Agent 的能力，把合适的子任务交出去，并接收远程 Agent 返回的 task 状态、消息和产物。
​        本阶段先不处理真实远程调用，是因为 A2A 一上来就接真实远程 Agent 会混入太多问题：远程 Agent 地址从哪里来，Agent Card 怎么读取，任务怎么发送，状态怎么轮询，失败怎么处理，结果怎么进入会话事件流。本阶段先用本地确定性数据把基本流程讲清楚，本章第二阶段再把远程 Agent 作为工具接入。

### 23.2.4 本阶段技术方案
​        本阶段继续使用第 22 章整理后的分层结构。A2A 的核心概念放在 `domain/a2a/entities.py`，入门演示逻辑放在 `application/a2a_intro_service.py`，HTTP 请求响应模型放在 `schemas/a2a.py`，路由放在 `presentation/http/routes/a2a.py`。前端新增 `a2a-api.ts` 和 `A2aPanel`，再把它接入 `ToolPreviewPanel` 的环境页签。
​        后端实现采用“确定性演示服务”的方式。`A2aIntroService` 不连接外部 Agent，而是返回固定角色说明、固定示例 Agent Card，并在收到 message 后生成一个模拟 task。这个 task 带有 `read_agent_card`、`select_remote_agent`、`message/send` 和 `task_completed` 四个步骤，让读者清楚看到一次 A2A 调用的顺序。
​        前端实现同样只展示入门信息。它不会提供“调用远程 Agent”的按钮，因为真实调用路径还没有进入工具体系。环境页签展示 A2A 概念和示例 Agent Card，是为了让用户知道系统接下来会具备远程 Agent 协作能力。等本章第二阶段把 A2A 接成工具后，具体调用结果才进入工具页签和事件流。

### 23.2.6 实施步骤
​        本阶段实施顺序和第 21 章 MCP 入门很相似：先定义领域对象，再写应用服务，再写 Schema 和路由，最后接前端面板。区别在于，A2A 的概念更偏 Agent 协作，所以领域对象会围绕 Agent Card、Message、Task 和 Step 展开。

#### 23.2.6.1 定义 A2A 角色模型
​        `A2aRole` 用来描述 A2A 中的核心角色。它包含名称、职责，以及在 AtlasAgent 项目里的映射位置。

```Python
@dataclass(slots=True)
class A2aRole:
    name: str
    responsibility: str
    system_mapping: str
```

​        本阶段会返回四个角色。Host Agent 是发起任务的一方，负责选择远程 Agent、发送消息并接收结果。Remote Agent 是被调用的一方，接收任务并返回消息、状态或 artifact。Agent Card 是远程 Agent 的名片，描述名称、地址、能力和输入输出模式。Task 则代表一次跨 Agent 协作任务，包含输入消息、执行状态和输出结果。
​        这些概念在后续章节都会继续出现。本章第二阶段会读取远程 Agent Card 并注册成可调用工具；第 24 章的多 Agent 编排会把多个 Agent 协作放进更大的任务流；后面的 Agent Runner 和任务恢复也会关心远程任务状态。

#### 23.2.6.2 定义 Agent Card 和能力模型
​        A2A 中，Host 在调用远程 Agent 之前，需要先知道远程 Agent 是谁、能做什么、在哪里调用、支持什么输入输出。这个信息由 Agent Card 承载。本阶段用 `A2aAgentCard` 表示最小模型。

```Python
@dataclass(slots=True)
class A2aCapability:
    name: str
    description: str
    example: str

@dataclass(slots=True)
class A2aAgentCard:
    name: str
    description: str
    url: str
    version: str
    capabilities: list[A2aCapability]
    default_input_modes: list[str]
    default_output_modes: list[str]
```

​        `A2aCapability` 描述远程 Agent 的单项能力，例如 `research_brief` 或 `source_outline`。`A2aAgentCard` 则把多个能力组织在一起，并提供远程 Agent 的地址、版本、默认输入模式和输出模式。这个结构类似 MCP 的 tools/list，但它描述的是一个 Agent，而不是一个普通工具集合。
​        本阶段的示例 URL 使用课程内置示例地址，不会真实访问。它的作用是让 Agent Card 看起来像真实远程 Agent 的描述，同时不引入外部网络依赖。

#### 23.2.6.3 定义 message 和 task 演示模型
​        A2A 的任务交互不是普通函数调用，而是消息和任务状态。为了展示这条链路，本阶段定义 `A2aMessagePart`、`A2aTaskStep` 和 `A2aMessageDemo`。

```Python
@dataclass(slots=True)
class A2aMessagePart:
    kind: str
    text: str

@dataclass(slots=True)
class A2aTaskStep:
    index: int
    action: str
    detail: str

@dataclass(slots=True)
class A2aMessageDemo:
    remote_agent: str
    task_id: str
    status: str
    input_message: list[A2aMessagePart]
    output_message: list[A2aMessagePart]
    steps: list[A2aTaskStep]
```

​        `A2aMessagePart` 目前只使用 text，但保留 `kind` 是为了后续扩展文件、数据和 artifact。`A2aTaskStep` 用于展示一次调用中发生的关键动作。`A2aMessageDemo` 则汇总远程 Agent、task id、状态、输入消息、输出消息和步骤。这个结构不是完整 A2A 规范实现，而是本阶段的教学最小模型。

#### 23.2.6.4 编写 A2aIntroService
​        `A2aIntroService` 是本阶段的应用服务。它的 docstring 明确说明本阶段边界：只用确定性数据模拟 Agent Card 和 `message/send`，本章第二阶段再接真实远程 Agent 调用。

```Python
class A2aIntroService:
    """第 34 章的 A2A 入门应用服务。

    A2A 解决的是 Agent 和 Agent 之间如何互相发现、发送任务、返回结果。
    本章先用确定性数据模拟 Agent Card 和 message/send，
    让读者理解协议边界。第 35 章再接入真实远程 Agent 调用。
    """
```

​        这个服务有三个核心方法：`list_roles()` 返回概念说明，`get_demo_agent_card()` 返回示例 Agent Card，`send_demo_message()` 模拟一次消息发送。这样路由层只负责 HTTP 转换，A2A 入门逻辑集中在应用服务里。

#### 23.2.6.5 返回 A2A 核心角色
​        `list_roles()` 返回 Host Agent、Remote Agent、Agent Card 和 Task。每个角色都有职责说明和项目映射。

```Python
def list_roles(self) -> list[A2aRole]:
    return [
        A2aRole(
            name="Host Agent",
            responsibility="发起任务的一方，负责选择远程 Agent、发送消息并接收结果。",
            system_mapping="AtlasAgent 主 API 中的 Agent Runner 或 A2A 工具调用方。",
        ),
        A2aRole(
            name="Remote Agent",
            responsibility="被调用的一方，接收任务并返回消息、状态或 artifact。",
            system_mapping="外部可协作 Agent，例如研究 Agent、代码 Agent、文档 Agent。",
        ),
    ]
```

​        代码里还会返回 Agent Card 和 Task。这里最值得注意的是 `system_mapping` 字段。它把抽象协议角色映射回当前项目，让读者知道这些概念以后会落在哪里。Host Agent 不是虚构角色，它会对应当前 API 中的 Agent Runner 或 A2A 工具调用方；Remote Agent 则是外部可协作 Agent。

#### 23.2.6.6 返回示例 Agent Card
​        `get_demo_agent_card()` 返回一个示例远程 Agent：`ResearchAssistantAgent`。

```Python
return A2aAgentCard(
    name="ResearchAssistantAgent",
    description="一个模拟的远程研究 Agent，擅长把问题拆成检索要点并返回摘要。",
    url="https://agents.example.com/research",
    version="0.1.0",
    capabilities=[
        A2aCapability(
            name="research_brief",
            description="根据用户问题整理研究摘要和后续建议。",
            example="帮我调研某个技术方案的优缺点。",
        ),
        A2aCapability(
            name="source_outline",
            description="把资料来源整理成结构化提纲。",
            example="把搜索结果整理成可写文章的大纲。",
        ),
    ],
    default_input_modes=["text/plain"],
    default_output_modes=["text/plain", "application/json"],
)
```

​        这个 Agent Card 不是为了真实调用，而是为了让读者看到远程 Agent 应该如何描述自己。Host Agent 需要根据这些信息判断远程 Agent 是否适合当前任务。如果一个远程 Agent 只声明了写作能力，却让它做代码审查，选择本身就不合理。

#### 23.2.6.7 模拟 message/send
​        `send_demo_message()` 接收用户消息，先做空字符串校验。空消息会抛出 `AppException`，不会返回一个无意义的 completed task。

```Python
clean_message = message.strip()
if not clean_message:
    raise AppException(
        message="a2a demo message is required",
        code=400,
        status_code=400,
    )
```

​        校验通过后，服务读取示例 Agent Card，生成一个 `a2a-demo-...` 开头的 task id，并构造四个步骤：读取 Agent Card、选择 Remote Agent、发送 `message/send`、远程 Agent 返回 completed。这个流程就是本阶段最核心的教学内容。

```Python
steps = [
    A2aTaskStep(index=1, action="read_agent_card", detail="Host 先读取远程 Agent Card。"),
    A2aTaskStep(index=2, action="select_remote_agent", detail=f"根据任务内容选择远程 Agent：{card.name}。"),
    A2aTaskStep(index=3, action="message/send", detail="Host 把用户任务包装成 A2A message。"),
    A2aTaskStep(index=4, action="task_completed", detail="远程 Agent 返回任务状态和输出消息。"),
]
```

​        返回结果中的 `output_message` 会明确说明这是本阶段模拟响应，本章第二阶段才接入真实远程 Agent 调用。这样用户不会误以为这里已经进行了真实 A2A 网络请求。

#### 23.2.6.8 定义 API Schema
​        `api/app/schemas/a2a.py` 把领域对象转换成 HTTP 响应模型。概念响应包含 roles、protocol 和 next_step；Agent Card 响应包含名称、描述、URL、版本、能力和输入输出模式；message 请求只需要一个 message 字段。

```Python
class A2aMessageSendRequest(BaseModel):
    message: str = Field(min_length=1, max_length=4000)

class A2aMessageDemoResponse(BaseModel):
    remote_agent: str
    task_id: str
    status: str
    input_message: list[A2aMessagePartResponse]
    output_message: list[A2aMessagePartResponse]
    steps: list[A2aTaskStepResponse]
```

​        `message` 使用最小长度和最大长度限制，是为了让接口边界明确。A2A 消息未来可能包含文件、结构化数据和 artifact，但本阶段先只允许文本，这样概念更聚焦。

#### 23.2.6.14 接入页面状态和工具预览


​        这样一来，右侧环境页签会依次展示 Sandbox、MCP、A2A 和 VNC。这个顺序也符合当前项目能力演进：先看执行环境，再看外部工具协议，再看远程 Agent 协作，再看浏览器远程桌面。

### 23.2.7 关键理解
​        本阶段最重要的理解，是 A2A 和 MCP 解决的问题不同。MCP 让 Agent 使用外部工具；A2A 让 Agent 与另一个 Agent 协作。工具通常是一个动作或资源入口，远程 Agent 则可能有自己的任务理解、计划、执行和结果整理能力。
​        第二个关键点是 Agent Card。Host Agent 不应该盲目调用一个远程地址，它要先读取 Agent Card，知道对方是谁、能做什么、支持哪些输入输出模式，再决定是否把任务交给它。Agent Card 就像远程 Agent 的能力声明和调用说明。
​        第三个关键点是 Task。A2A 协作不是简单函数返回，远程 Agent 可能需要一段时间执行，也可能返回状态、消息、artifact 或后续动作。本阶段先用 completed 的模拟 task 展示基本结构，后续真实接入时再处理 running、failed、artifact 等情况。
​        第四个关键点是 Host Agent 仍然要负责整体任务边界。A2A 并不意味着主 Agent 把任务完全甩给远程 Agent。Host 要先判断任务是否适合远程协作，再根据 Agent Card 选择合适对象，然后把输入包装成对方能理解的 message。远程 Agent 返回结果以后，Host 还要决定结果是否足够、是否需要继续追问、是否要把结果写入当前会话或合并到最终回答。也就是说，A2A 是协作协议，不是责任转移协议。
​        第五个关键点是 A2A 的结果需要回到当前产品体验里。用户在 AtlasAgent 工作台里发起任务，就应该能在同一个工作台里看到远程 Agent 的参与痕迹。本阶段先把概念展示在环境页签，本章第二阶段再让调用结果进入工具事件流。这个设计能避免远程 Agent 变成后端不可见的黑盒，也方便后续做任务回放、错误排查和引用说明。
​        第六个关键点是 message part 的扩展空间。现在 `A2aMessagePart` 只有 `kind` 和 `text`，看起来很简单，但它已经暗示了 A2A 后续可以承载更多内容形态。远程 Agent 协作不一定只传纯文本，未来可能传文件、数据片段、图像、代码补丁、artifact 引用或结构化 JSON。先把 part 抽出来，而不是把 message 简化成一个字符串，可以让后续扩展更自然。
​        第七个关键点是每一次远程协作都要能被追踪。只要任务跨出了当前进程，就必须留下远程 Agent、task id、输入和输出，否则后续无法回放。

### 23.2.8 技术难点与亮点
​        本阶段的难点在于不要把 A2A 提前做成真实调用。真实 A2A 会涉及远程地址、网络错误、任务状态、权限和结果同步，如果一上来全部实现，读者会被工程细节淹没。本阶段只用确定性服务讲清楚角色和流程，边界更清楚。
​        第二个亮点是分层落点很自然。A2A 领域对象放在 `domain/a2a`，入门服务放在 `application`，HTTP 入口放在 `presentation/http/routes`，前端只做展示。第 22 章刚整理出的结构在这里立即发挥作用，新增协议能力时不需要重新想目录。
​        第三个亮点是前端没有急着做调用按钮。入门面板只展示概念和 Agent Card，避免用户误以为已经可以真实调远程 Agent。真正的调用会在本章第二阶段进入工具系统，到时候再让调用结果进入 `tool_called` 和工具预览卡片。
​        第四个难点是不要把 Agent Card 理解成普通配置。配置通常由本项目维护，Agent Card 则是远程 Agent 对外声明自己的能力。Host 可以缓存、展示或校验它，但不能把它当成永远可靠的本地事实。真实接入时，Agent Card 可能版本变化、能力变化、地址变化，也可能因为远程 Agent 不可用而读取失败。本阶段先用固定数据，是为了讲清结构；后续真实调用必须把这些失败暴露出来。
​        第五个亮点是本阶段的后端接口与前端展示保持了同一套叙事。后端 `/concepts` 解释角色，前端显示核心角色；后端 `/demo/agent-card` 返回示例名片，前端显示 Agent Card；后端 `/demo/message` 演示调用流程，命令行验证展示步骤。每个接口都有清楚的教学目的，而不是为了“多做几个接口”凑功能。
​        第六个难点是避免和现有 Agent Task 混淆。当前项目已经有本地计划任务、Redis Stream 后台执行任务和会话事件。A2A Task 是跨 Agent 协作任务，它将来会进入当前任务体系，但概念上不等于本地 Redis 任务。本阶段用 `a2a-demo-...` 作为 task id 前缀，就是为了让读者知道它属于 A2A 演示，不是当前会话里的本地任务记录。

### 23.2.9 面试考点
​        如果面试官问“A2A 和 MCP 有什么区别”，可以回答：MCP 关注 Agent 如何使用外部工具、资源和提示词；A2A 关注 Agent 如何发现并协作调用另一个 Agent。MCP 的对象更像工具服务，A2A 的对象是具备任务处理能力的远程 Agent。
​        如果被问到“Agent Card 的作用是什么”，要说明它是远程 Agent 的能力声明。Host 通过 Agent Card 了解远程 Agent 的名称、地址、版本、能力、输入模式和输出模式，再决定是否发送任务。
​        如果被问到“为什么本阶段不真实调用远程 Agent”，可以回答：本阶段是协议入门，先用确定性接口讲清角色和流程。真实调用涉及网络、状态、失败、权限和结果同步，放到本章第二阶段作为工具接入更合适。
​        如果被问到“Task 和普通函数调用有什么不同”，重点说明 Task 有状态和过程。远程 Agent 可能异步执行，结果不一定立即返回一个字符串，它可能返回消息、artifact、状态变化和后续事件。本阶段只模拟 completed，是为了先展示最小结构。

### 23.2.11 代码串联阅读
​        这一阶段的代码虽然分散在后端和前端多个文件里，但阅读顺序很清楚。先看领域对象，再看应用服务，再看 Schema 和路由，最后看前端面板。按这个顺序读，比从页面开始倒着找接口更容易理解 A2A 是怎样进入项目的。

#### 23.2.11.1 从 domain/a2a/entities.py 开始
​        `domain/a2a/entities.py` 是本阶段最适合先读的文件。它没有 FastAPI、没有 Pydantic、没有 React，也没有网络调用，只定义 A2A 入门需要的几个对象：`A2aRole`、`A2aCapability`、`A2aAgentCard`、`A2aMessagePart`、`A2aTaskStep` 和 `A2aMessageDemo`。这些对象就是本阶段概念的代码形态。
​        读这个文件时，要特别注意 `A2aAgentCard` 和 `A2aMessageDemo`。前者描述远程 Agent 的能力边界，后者描述一次 message/send 的结果。一个是“调用前如何认识对方”，一个是“调用后如何记录过程”。这两个对象串起来，基本就能理解本阶段为什么要先讲 Agent Card，再讲 message/send。

#### 23.2.11.2 再看 application/a2a_intro_service.py
​        `A2aIntroService` 把领域对象组织成可调用的应用服务。`list_roles()` 面向概念说明，`get_demo_agent_card()` 面向示例名片，`send_demo_message()` 面向调用流程演示。它没有直接返回 Pydantic 模型，也没有直接处理 HTTP 请求，这一点和第 22 章的分层规则是一致的。
​        这里最关键的是 `send_demo_message()`。它先校验输入，再读取 Agent Card，再生成 task id，最后构造步骤和输出消息。虽然它没有访问远程网络，但流程顺序已经和真实 A2A 的基本心智模型一致。后续真实接入时，固定的 output_text 会被远程 Agent 响应替代，固定的 steps 会被真实调用过程和状态更新替代。

#### 23.2.11.3 然后看 schemas/a2a.py
​        `schemas/a2a.py` 负责把后端概念转换成 HTTP 接口稳定结构。它里面的 `A2aConceptsResponse`、`A2aAgentCardResponse` 和 `A2aMessageDemoResponse` 分别对应三个接口。这样前端不需要理解 dataclass，也不需要依赖应用服务内部对象。
​        Schema 层还有一个很实用的边界：`A2aMessageSendRequest` 对 message 做长度限制。入门章节只允许一段文本任务，能避免接口变成无限制的大输入入口。真实 A2A 支持文件和 artifact 时，也应该通过新的结构显式表达，而不是把所有内容都塞进一个巨大字符串。

#### 23.2.11.4 接着看 presentation/http/routes/a2a.py
​        路由文件展示了第 22 章分层重构后的落点。A2A 的 HTTP 入口不在旧的 `app/api` 下，而是在 `app/presentation/http/routes/a2a.py`。它只做三件事：创建入门服务，把领域对象转换成响应模型，暴露 HTTP 接口。
​        `GET /concepts` 用于展示概念，`GET /demo/agent-card` 用于展示示例 Agent Card，`POST /demo/message` 用于模拟 message/send。路由层没有把 demo 数据写死在函数里，而是调用 `A2aIntroService`。这样后续真实接入时，可以新增真实服务，而不需要把整个 HTTP 文件改成业务逻辑仓库。

#### 23.2.11.5 最后看前端 a2a-api 和 A2aPanel
​        前端的 `a2a-api.ts` 只封装 concepts 和 Agent Card 两个读取接口。它没有封装 message/send 给页面按钮使用，这个选择是有意的：本阶段 UI 只展示能力环境，不触发真实协作。`A2aPanel` 则把核心角色和示例 Agent Card 展示出来，让用户在环境页签里看到系统正在引入远程 Agent 协作能力。
​        `ToolPreviewPanel` 把 `A2aPanel` 放在环境页签，与 Sandbox、MCP 和 VNC 并列。这个位置说明 A2A 目前还是“能力环境展示”。当本章第二阶段把 A2A 调用接入工具协议后，调用结果才会进入工具页签。这样前端结构和后端实现阶段保持一致，不会提前展示尚未完成的交互。
​        读前端代码时还要注意 `LoadState` 的一致性。A2A concepts 和 Agent Card 都按 loading、error、ready 三种状态展示，这和 MCP、Sandbox、VNC 的处理方式相同。外部能力越多，前端越需要统一状态表达。否则每个面板都用自己的加载和错误样式，右侧工作区很快会失去一致性。
​        `page.tsx` 中的刷新逻辑也值得看。A2A 有自己的刷新函数，只重新请求 concepts 和 Agent Card，不影响会话消息、文件、MCP 或 VNC。这样用户刷新 A2A 面板时，不会触发无关数据加载。这个小细节体现的是前端状态边界：能力面板可以独立刷新，任务执行流和会话数据不应该被连带扰动。

### 23.2.12 阶段小结
​        本阶段完成了 A2A 协议入门。后端新增 A2A 领域对象、入门应用服务、API Schema 和 HTTP 路由，提供概念说明、示例 Agent Card 和 message/send 演示接口。前端新增 A2A 面板，把 Host Agent、Remote Agent、Agent Card 和 Task 的概念展示到工具预览环境区。
​        这一阶段的重点不是远程调用，而是建立正确边界。MCP 是工具协议，A2A 是 Agent 协作协议。Agent Card 是远程 Agent 的能力声明，message/send 是 Host 把任务交给远程 Agent 的入口，Task 是协作过程和结果的承载。理解这些，本章第二阶段把 A2A 接成工具时才不会混乱。
​        从工程连续性看，本阶段也验证了第 22 章分层重构的价值。新的协议能力可以自然落到 `domain`、`application`、`schemas` 和 `presentation/http` 中，前端也能按已有工具预览结构接入新面板。也就是说，A2A 入门不是孤立章节，它同时证明了后端分层和前端工具预览都具备继续扩展的空间。
​        更重要的是，本阶段把“远程 Agent 参与任务”这件事先放到了可解释的位置。先解释角色、名片、消息和任务，再去实现真实调用，后续代码就不会变成一组看不出意图的 HTTP 请求封装。
​        这种先解释再接入的节奏，也能减少后续调试时的概念混乱。

```Python
import uuid
from abc import ABC, abstractmethod
from typing import Any

import httpx

from app.core.a2a_config import A2aAgentConfig, load_a2a_config
from app.core.exceptions import AppException
from app.domain.a2a.entities import (
    A2aAgentCard,
    A2aCapability,
    A2aMessagePart,
    A2aRemoteAgentInfo,
    A2aTaskResult,
    A2aTaskStep,
)

class A2aTransportClient(ABC):
    """A2A 传输层客户端基类。

    上层应用服务只关心“列出 Agent Card”和“发送任务消息”。
    具体是内置 demo、HTTP 远程服务，还是后续更完整的 A2A SDK，
    都封装在 transport client 中。
    """

    def __init__(self, agent_key: str, config: A2aAgentConfig) -> None:
        self.agent_key = agent_key
        self.config = config

    @abstractmethod
    def get_agent_card(self) -> A2aAgentCard:
        """读取远程 Agent Card。"""

    @abstractmethod
    def send_message(self, message: str) -> A2aTaskResult:
        """向远程 Agent 发送一条任务消息。"""

class DemoA2aTransportClient(A2aTransportClient):
    """内置 A2A 演示客户端。

    它模拟真实远程 Agent 的 Agent Card 和 message/send 响应，
    不需要额外启动服务，适合课程稳定验证完整工具事件链路。
    """

    def get_agent_card(self) -> A2aAgentCard:
        # 1. demo transport 不发网络请求，直接把配置转换成 Agent Card。
        #    这样本地环境不用启动远程服务，也能跑通 Host 读取 Agent Card 的流程。
        return _agent_card_from_config(self.config)

    def send_message(self, message: str) -> A2aTaskResult:
        # 1. 清理用户任务文本。远程 Agent 不应该收到空消息。
        clean_message = message.strip()
        if not clean_message:
            raise AppException(
                message="A2A message is required",
                code=400,
                status_code=400,
            )

        # 2. 为本次远程调用生成一个模拟 task_id。
        #    真实 A2A 服务通常会返回自己的任务 ID，本章用 uuid 模拟。
        task_id = f"a2a-task-{uuid.uuid4()}"

        # 3. 组装统一的 A2aTaskResult。
        #    ReAct 工具和 HTTP API 都依赖这个结构，所以这里不直接返回 dict。
        return A2aTaskResult(
            agent_key=self.agent_key,
            remote_agent=self.config.name,
            task_id=task_id,
            status="completed",
            input_message=[A2aMessagePart(kind="text", text=clean_message)],
            output_message=[
                A2aMessagePart(
                    kind="text",
                    text=(
                        f"{self.config.name} 已完成远程协作："
                        f"围绕“{clean_message}”整理了摘要、关键点和下一步建议。"
                    ),
                )
            ],
            steps=[
                A2aTaskStep(
                    index=1,
                    action="agent_card/read",
                    detail=f"读取远程 Agent Card：{self.config.name}。",
                ),
                A2aTaskStep(
                    index=2,
                    action="message/send",
                    detail="Host Agent 把用户任务包装成 A2A message 并发送。",
                ),
                A2aTaskStep(
                    index=3,
                    action="task/completed",
                    detail="远程 Agent 返回 completed 状态和输出消息。",
                ),
            ],
        )

class HttpA2aTransportClient(A2aTransportClient):
    """最小 HTTP A2A 客户端。

    本章先约定远程服务暴露两个 HTTP 接口：
    GET /agent-card 和 POST /message/send。
    后续如果接入更完整 A2A 协议，可以继续替换这里的传输细节。
    """

    def get_agent_card(self) -> A2aAgentCard:
        # 1. 向远程 Agent 读取 Agent Card。
        #    本章约定真实 HTTP Agent 暴露 GET /agent-card。
        payload = self._request("GET", "/agent-card")

        # 2. 把远程响应里的 capabilities 转成领域对象。
        #    如果远程字段缺失，使用空字符串兜底，避免前端渲染崩掉。
        capabilities = [
            A2aCapability(
                name=str(item.get("name") or ""),
                description=str(item.get("description") or ""),
                example=str(item.get("example") or item.get("description") or ""),
            )
            for item in payload.get("capabilities", [])
            if isinstance(item, dict)
        ]

        # 3. 返回统一 Agent Card。
        #    远程没返回的基础字段，使用配置文件中的值补齐。
        return A2aAgentCard(
            name=str(payload.get("name") or self.config.name),
            description=str(payload.get("description") or self.config.description),
            url=str(payload.get("url") or self.config.url),
            version=str(payload.get("version") or self.config.version),
            capabilities=capabilities,
            default_input_modes=list(payload.get("default_input_modes") or ["text"]),
            default_output_modes=list(payload.get("default_output_modes") or ["text"]),
        )

    def send_message(self, message: str) -> A2aTaskResult:
        # 1. 调用远程 Agent 的 message/send。
        #    本章先约定请求体只有 message，后续可扩展 artifacts、metadata 等字段。
        payload = self._request("POST", "/message/send", json={"message": message})

        # 2. 解析远程输入输出消息。
        #    远程服务可能不返回 input_message，所以 fallback 使用本次发送的 message。
        input_message = _message_parts_from_payload(payload.get("input_message"), message)
        output_message = _message_parts_from_payload(payload.get("output_message"), "")

        # 3. 解析远程执行步骤。
        #    steps 会进入前端工具预览，帮助用户看到远程 Agent 做过哪些动作。
        steps = [
            A2aTaskStep(
                index=int(item.get("index") or index),
                action=str(item.get("action") or "remote_step"),
                detail=str(item.get("detail") or ""),
            )
            for index, item in enumerate(payload.get("steps", []), start=1)
            if isinstance(item, dict)
        ]

        # 4. 包装成统一任务结果。
        #    即使真实远程 Agent 字段不完整，主 API 也尽量返回稳定结构。
        return A2aTaskResult(
            agent_key=self.agent_key,
            remote_agent=str(payload.get("remote_agent") or self.config.name),
            task_id=str(payload.get("task_id") or f"a2a-task-{uuid.uuid4()}"),
            status=str(payload.get("status") or "completed"),
            input_message=input_message,
            output_message=output_message,
            steps=steps,
        )

    def _request(
        self,
        method: str,
        path: str,
        json: dict[str, Any] | None = None,
    ) -> dict[str, Any]:
        # 1. 根据配置里的 base url 拼出远程接口地址。
        url = f"{self.config.url.rstrip('/')}{path}"
        try:
            # 2. 发送 HTTP 请求，并使用配置里的 timeout 避免调用长期卡住。
            response = httpx.request(
                method,
                url,
                json=json,
                timeout=self.config.timeout_seconds,
            )
            # 3. 非 2xx 响应直接抛出，统一转成 AppException 给上层。
            response.raise_for_status()
        except httpx.HTTPError as exc:
            raise AppException(
                message=f"A2A HTTP request failed: {exc}",
                code=502,
                status_code=502,
            ) from exc

        # 4. 兼容两种响应格式：
        #    - 直接返回业务 JSON
        #    - 返回统一 ApiResponse，其中业务数据在 data 字段里
        payload = response.json()
        if isinstance(payload, dict) and "data" in payload and isinstance(payload["data"], dict):
            return payload["data"]
        return payload if isinstance(payload, dict) else {}

class A2aClientManager:
    """A2A Client 管理器。

    它读取 A2A 配置，按 agent_key 创建对应传输客户端，
    并向应用服务提供统一的 list / card / message 调用方法。
    """

    def __init__(self) -> None:
        # 1. 读取并缓存 A2A 配置。
        #    load_a2a_config 本身带 lru_cache，所以多次创建 manager 不会重复读文件。
        self.config = load_a2a_config()

    # ===================== 第1步：读取远程 Agent 配置列表 =====================
    def list_agents(self) -> list[A2aRemoteAgentInfo]:
        """返回全部配置过的远程 Agent。"""

        # 1. 遍历 YAML 中声明的 agents。
        # 2. 把配置模型转换成领域对象，供 API 和前端状态面板展示。
        return [
            A2aRemoteAgentInfo(
                key=key,
                enabled=agent.enabled,
                transport=agent.transport,
                name=agent.name,
                description=agent.description,
                url=agent.url,
                version=agent.version,
                capabilities=[
                    A2aCapability(
                        name=capability.name,
                        description=capability.description,
                        example=capability.description,
                    )
                    for capability in agent.capabilities
                ],
            )
            for key, agent in self.config.agents.items()
        ]

    # ===================== 第2步：读取 Agent Card =====================
    def get_agent_card(self, agent_key: str | None = None) -> A2aAgentCard:
        """读取指定远程 Agent 的 Agent Card。"""

        # 1. 如果调用方没有传 agent_key，就使用配置中的默认 Agent。
        key = agent_key or self.config.a2a.default_agent

        # 2. 校验 Agent 是否存在且启用，避免调用被禁用的外部服务。
        agent = self._get_enabled_agent(key)

        # 3. 根据 transport 创建 client，并读取 Agent Card。
        return self._build_transport(key, agent).get_agent_card()

    # ===================== 第3步：发送任务消息 =====================
    def send_message(self, agent_key: str | None, message: str) -> A2aTaskResult:
        """向指定远程 Agent 发送一条任务消息。"""

        # 1. 没有指定 agent_key 时使用默认远程 Agent。
        key = agent_key or self.config.a2a.default_agent

        # 2. 先校验配置状态，再创建对应 transport。
        agent = self._get_enabled_agent(key)

        # 3. 真正调用远程 Agent，并返回统一任务结果。
        return self._build_transport(key, agent).send_message(message)

    def _get_enabled_agent(self, agent_key: str) -> A2aAgentConfig:
        # 1. 检查配置中是否存在这个 Agent。
        agent = self.config.agents.get(agent_key)
        if agent is None:
            raise AppException(
                message=f"A2A agent not found: {agent_key}",
                code=404,
                status_code=404,
            )

        # 2. 检查是否启用。禁用的 Agent 不能被工具和 API 调用。
        if not agent.enabled:
            raise AppException(
                message=f"A2A agent is disabled: {agent_key}",
                code=400,
                status_code=400,
            )
        return agent

    def _build_transport(
        self,
        agent_key: str,
        agent: A2aAgentConfig,
    ) -> A2aTransportClient:
        # 1. demo transport 走内置模拟器，适合课程稳定验证。
        if agent.transport == "demo":
            return DemoA2aTransportClient(agent_key, agent)

        # 2. http transport 走真实远程 Agent 服务。
        if agent.transport == "http":
            return HttpA2aTransportClient(agent_key, agent)

        # 3. 配置里出现未知 transport 时返回明确错误。
        raise AppException(
            message=f"unsupported A2A transport: {agent.transport}",
            code=500,
            status_code=500,
        )

def build_a2a_client_manager() -> A2aClientManager:
    return A2aClientManager()

def _agent_card_from_config(config: A2aAgentConfig) -> A2aAgentCard:
    return A2aAgentCard(
        name=config.name,
        description=config.description,
        url=config.url,
        version=config.version,
        capabilities=[
            A2aCapability(
                name=capability.name,
                description=capability.description,
                example=capability.description,
            )
            for capability in config.capabilities
        ],
        default_input_modes=["text"],
        default_output_modes=["text"],
    )

def _message_parts_from_payload(value: object, fallback: str) -> list[A2aMessagePart]:
    if not isinstance(value, list):
        return [A2aMessagePart(kind="text", text=fallback)] if fallback else []
    parts: list[A2aMessagePart] = []
    for item in value:
        if isinstance(item, dict):
            parts.append(
                A2aMessagePart(
                    kind=str(item.get("kind") or item.get("type") or "text"),
                    text=str(item.get("text") or ""),
                )
            )
    return parts
```

##### 23.3.6.4.1 代码讲解

​        这个文件是本阶段后端最关键的部分。

​        `A2aTransportClient` 是抽象基类，它定义两个方法：

```Plain
get_agent_card()
send_message()
```

​        `DemoA2aTransportClient` 是内置演示实现。它不访问网络，直接返回确定性结果。

​        `HttpA2aTransportClient` 是真实 HTTP 接入示例。它约定远程 Agent 提供：

```Plain
GET  /agent-card
POST /message/send
```

​        `A2aClientManager` 负责：

​        放到工程语境里看，第一，读取配置；第二，列出远程 Agent；第三，根据 agent_key 找到配置；第四，根据 transport 创建对应 client；第五，对上层暴露统一方法。这些点放在一起看，构成了本阶段叙述中需要连续理解的一条线索，而不是彼此孤立的项目清单。

##### 23.3.6.4.2 为什么要分 manager 和 transport client

​        因为“选择哪个远程 Agent”和“怎么调用这个远程 Agent”是两件事。

​        manager 负责选择和管理。

​        transport client 负责具体调用。

​        这样后续加入更多传输方式时，不需要改应用服务和路由。

#### 23.3.6.5 实现 A2A 应用服务

```Python
from app.domain.a2a.entities import A2aAgentCard, A2aRemoteAgentInfo, A2aTaskResult
from app.infrastructure.a2a.client import A2aClientManager, build_a2a_client_manager

class A2aService:
    """真实 A2A 工具接入的应用服务。

    第 34 章只做概念演示；第 35 章开始，这个服务负责读取 A2A 配置、
    获取远程 Agent Card，并向远程 Agent 发送任务消息。
    """

    def __init__(self, manager: A2aClientManager | None = None) -> None:
        # 1. manager 负责传输层细节，service 负责应用层语义。
        self.manager = manager or build_a2a_client_manager()

    # ===================== 第1步：读取远程 Agent 配置状态 =====================
    def list_agents(self) -> list[A2aRemoteAgentInfo]:
        """返回所有配置过的远程 Agent。"""

        # 1. 这里不直接读取 YAML，而是委托 manager。
        #    service 只表达“列出远程 Agent”这个应用动作。
        return self.manager.list_agents()

    # ===================== 第2步：读取远程 Agent Card =====================
    def get_agent_card(self, agent_key: str | None = None) -> A2aAgentCard:
        """读取指定远程 Agent 的 Agent Card。"""

        # 1. agent_key 可以为空。为空时 manager 会使用配置里的默认 Agent。
        # 2. manager 负责选择 demo/http transport 并读取 Agent Card。
        return self.manager.get_agent_card(agent_key=agent_key)

    # ===================== 第3步：向远程 Agent 发送任务 =====================
    def send_message(self, agent_key: str | None, message: str) -> A2aTaskResult:
        """向远程 Agent 发送一条任务消息，并返回统一任务结果。"""

        # 1. Route 和 AgentTool 都会调用这个方法。
        # 2. 统一从这里进入 manager，避免两边各自实现一套远程调用逻辑。
        # 3. 返回 A2aTaskResult，供 API 响应或工具输出继续包装。
        return self.manager.send_message(agent_key=agent_key, message=message)
```

#### 23.3.6.7 把 A2A 注册成 AgentTool

​        创建 `api/app/infrastructure/agent_tools/a2a.py`。

​        完整代码如下：

```Python
import json

from app.application.a2a_service import A2aService
from app.domain.a2a.entities import A2aTaskResult
from app.domain.agent_core.tools import (
    AgentTool,
    ToolDefinition,
    ToolParameter,
    ToolRegistry,
)

def register_a2a_tools(
    registry: ToolRegistry,
    service: A2aService | None = None,
) -> None:
    """把 A2A 远程 Agent 调用入口注册成 AgentTool。

    第 35 章先注册一个通用 `a2a_call`。它通过 agent_key + message
    调用配置文件中的远程 Agent。后续多 Agent 编排章节会把不同角色
    组织成更完整的协作流程。
    """

    # 1. 创建或复用 A2A 应用服务。
    #    测试时可以传入 fake service，生产默认读取配置文件。
    a2a_service = service or A2aService()

    # 2. 注册一个通用 AgentTool。
    #    ReAct 执行计划时只需要知道工具名和参数 schema，不需要知道 A2A client 细节。
    registry.register(
        AgentTool(
            definition=ToolDefinition(
                name="a2a_call",
                description="调用一个已配置 A2A 远程 Agent 完成协作任务。",
                parameters=[
                    ToolParameter(
                        name="agent_key",
                        type="string",
                        description="A2A Agent 配置 key，例如 demo_researcher。",
                        required=False,
                    ),
                    ToolParameter(
                        name="message",
                        type="string",
                        description="要发送给远程 Agent 的任务消息。",
                    ),
                ],
            ),
            # 3. handler 是工具真正执行入口。
            #    AgentTool 会先校验参数，再把 agent_key/message 传给这里。
            handler=lambda agent_key="", message="": _format_a2a_result(
                a2a_service.send_message(
                    agent_key=str(agent_key or "") or None,
                    message=str(message),
                )
            ),
        )
    )

def _format_a2a_result(result: A2aTaskResult) -> str:
    """把 A2A 调用结果格式化成前端工具预览可识别的 JSON。"""

    # 1. 工具 output 目前是字符串，所以先把结构化结果序列化成 JSON。
    # 2. kind 是前端判断展示方式的关键字段；没有它就只能显示普通文本。
    # 3. input/output/steps 都保留下来，方便用户观察远程 Agent 的协作过程。
    return json.dumps(
        {
            "kind": "a2a_task_result",
            "agent_key": result.agent_key,
            "remote_agent": result.remote_agent,
            "task_id": result.task_id,
            "status": result.status,
            "input_message": [
                {"kind": part.kind, "text": part.text}
                for part in result.input_message
            ],
            "output_message": [
                {"kind": part.kind, "text": part.text}
                for part in result.output_message
            ],
            "steps": [
                {
                    "index": step.index,
                    "action": step.action,
                    "detail": step.detail,
                }
                for step in result.steps
            ],
        },
        ensure_ascii=False,
    )
```

### 23.3.7 关键理解

​        本阶段最重要的是理解 A2A 工具接入的位置。

​        A2A 不应该只是一个 API。

​        它应该进入 Agent 当前执行过程：

```Plain

```

​        第二个重点是理解 A2A 和 MCP 的区别。

```Plain
MCP：把外部能力包装成工具
A2A：把另一个 Agent 包装成协作者
```

​        第三个重点是配置驱动。

​        远程 Agent 信息写在 `api/config/a2a.yaml`，不是散落在代码里。

### 23.3.8 技术难点与亮点

​        项目亮点：
