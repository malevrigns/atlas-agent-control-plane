# 第二十三章. A2A 协议与工具接入

MCP 解决的是「Agent 怎么用工具」。文件系统、浏览器、搜索、业务系统，都是工具这一侧的事。系统再往前走一步，会出现另一种外部能力：把一部分任务交给另一个 Agent。那就是 A2A，Agent-to-Agent。它不是 MCP 的别名，抽象层级也不一样。

代码仍在 `backend/api-ts` 和 `frontend/web`。对照实现打开这两个 TypeScript 目录，不要再新建 Python 服务。

![远程能力同样收成可观察的卡片](../assets/ch12-tools.jpg)

## 远程的是 Agent，不是函数

Host Agent 是 AtlasAgent 自己，负责读用户目标、决定哪一段该留下、哪一段该送出去。Remote Agent 在别处运行，有自己的上下文、自己的工具、自己的失败方式。Agent Card 是它的名片：名字、能力列表、入口地址、也许还有认证提示。Task 是一次协作的单据，带着状态、消息和产物，而不是一次 RPC 的返回值。

一次说得过去的调用顺序是：先读 Agent Card，确认对方真的宣称能做这件事；再选中那个 Remote Agent；然后 `message/send`，把任务消息送过去；最后按 task 状态收结果。跳过名片直接 POST，等于在未知接口上赌字段名。

MCP 的 tools/call 通常是短的、同步味道更重的动作。A2A 的 task 可以很长，中间可能还要轮询、取消、取 artifact。把两者揉进同一个 client，错误处理会先崩溃。笔者把它们分成两块面板，不是为了多两个页签，是为了让「调工具」和「请另一个 Agent 办事」在工作台上先分开站。

远程 Agent 的失败是 dependency，不是我们业务 400。超时、幂等键、审计行，和调 MCP 时同一套纪律。HTTP 宿主必须允许列表，默认空。不要在前端把 A2A 配成「随便填一个 URL」。设置里保存的是名称和允许的 host，真正请求由控制平面发出。浏览器拿到的只是观察，不是 socket。

## 工作台已经会问，控制平面还在点头

`frontend/web/app/lib/a2a-api.ts` 打三个地址：

```ts
export function fetchA2aConcepts(): Promise<A2aConceptsData> {
  return requestApi<A2aConceptsData>("/api/a2a/concepts");
}

export function fetchA2aAgentCard(): Promise<A2aAgentCardData> {
  return requestApi<A2aAgentCardData>("/api/a2a/agents/demo_researcher/card");
}

export function fetchA2aAgents(): Promise<A2aRemoteAgentListData> {
  return requestApi<A2aRemoteAgentListData>("/api/a2a/agents");
}
```

`A2aPanel` 用这三份数据画「核心角色」「远程 Agent 列表」「示例 Agent Card」。刷新按钮重新拉一遍。类型写在 `frontend/web/app/types.ts` 里，字段名按远程协作来：roles、capability、endpoint。页面结构已经按「真有 Remote Agent」来长。

Hono 这一侧，这些路径目前都在 `stubRoutes()` 里。`/api/a2a/concepts` 和 `/api/a2a/agents` 返回 `{ items: [] }`。`/api/a2a/agents/demo_researcher/card` 没有单独实现，走不到一张真实名片，工作台会看到空列表或按空数据降级。Compose 仍传递 `A2A_CONFIG_PATH`，控制平面并没有在 TypeScript 里解析那份 YAML，更不会对远程地址发 `message/send`。

这和 MCP 同一类诚实。协议位留好了，Client 还在港口。旧的实现里曾经有过演示名片和 `a2a_call` 工具，那是演进史，不是现行运行时。现行 SSE 路径是 `streamUserMessage()`，事件序列是会话状态、消息、answer_delta、task_done，不会冒出一次远程 Agent 调用。

空列表仍然值得 curl。它证明鉴权、信封、CORS、前端 store 都通。等 `infrastructure/` 里出现 A2A client，application 里出现把远程 task 写成 `tool_called` 的服务，面板不用改契约，只要 `items` 里开始有人。

## 将来注册成工具时，不要另开一条河

远程 Agent 一旦能调用，就应该像 `search_web` 一样进入工具协议：名字、参数、输出、事件。中间时间线点那张卡片，右侧预览打开同一条 `tool_called`。不要为 A2A 单独做一套「协作消息流」，否则第 26 章的工作台又要分叉。

鉴权也不该跟 MCP 混用同一把随意 token。Remote Agent 有自己的 allowlist、自己的受众。第 31 章会把「外部集成」写成安全检查项；现在只要记住：浏览器拿不到远程密钥，控制平面也还没有把密钥写进 stub。

笔者不在这一章编造 `ResearchAssistantAgent` 已经上线的故事。演示数据很容易写，写了读者会以为 Compose 起了就能把任务派到另一台机器。派不出去。能看见的是面板、类型、空列表，以及「名片先于消息」这条纪律。

## 这一章留下了什么

A2A 与 MCP 的边界，一块会提问的前端面板，和 TypeScript 控制平面里尚未填上的 Client。下一章谈的是系统内部的多角色协作——那不是远程 Agent，是同一进程里的分工，更不该和 A2A 抢同一套名词。
