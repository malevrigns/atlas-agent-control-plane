## 50.1 本章目标

​        学完本章后，你将能够：

### 50.5.3 确认 UI 容器监听地址

​        打开 `ui/Dockerfile`，确认运行镜像中显式设置：

```Dockerfile
ENV HOSTNAME=0.0.0.0

```

#### 50.5.3.1 代码讲解

​        Next.js standalone 运行时会读取 `HOSTNAME` 和 `PORT`。

​        Docker 容器默认也有一个 `HOSTNAME` 环境变量，值通常是容器 ID。如果不显式设置，Next.js 可能只监听容器主机名，而不是监听所有网卡。

​        这会造成一个很隐蔽的问题：

```Plain
UI 进程已经启动
  |
  v
容器健康检查访问 localhost:3000 失败
  |
  v
UI 容器变成 unhealthy
  |
  v
Nginx 没有可用的 UI 上游
  |
  v
访问 http://localhost:8088 返回 502
```

​        所以这里明确绑定：

```Plain
0.0.0.0:3000
```

​        这样容器内健康检查、Nginx 和同一个 Docker 网络里的其他服务都能访问 UI。

## 50.10 常见问题

- 问题：页面样式没有变化怎么办？

​        解释：浏览器可能还在使用旧 UI 镜像或旧缓存。先执行 `docker compose build ui`，再执行 `docker compose up -d --force-recreate ui nginx`，然后强制刷新浏览器。

- 问题：页面还是整体滚动怎么办？

​        解释：检查 `ui/app/globals.css` 中 `html, body` 是否设置了 `height: 100%` 和 `overflow: hidden`。再检查 `ui/app/page.tsx` 外层是否是 `h-screen overflow-hidden`，左侧会话列表是否是 `overflow-y-auto`。

- 问题：访问 `http://localhost:8088` 返回 502 怎么办？

​        解释：先执行 `docker compose ps`。如果 `atlas-ui` 是 `unhealthy`，优先检查 `ui/Dockerfile` 中是否设置了 `HOSTNAME=0.0.0.0` 和 `PORT=3000`。修改后重新执行 `docker compose build ui` 和 `docker compose up -d --force-recreate ui nginx`。

- 问题：页面能访问，但 `atlas-nginx` 显示 `unhealthy` 怎么办？

​        解释：这通常是 Nginx 容器内健康检查访问了 IPv6 的 `localhost`。本章把 Nginx 健康检查改成 `http://127.0.0.1/`，确保健康检查访问 IPv4 监听地址。

- 问题：右侧工具预览没有出现怎么办？

​        解释：需要先发送会产生 `tool_called` 事件的任务，再点击时间线里的工具节点。

- 问题：为什么本章没有新增后端接口？

​        解释：第 49 章已经做了最终验收接口。本章目标是前端体验打磨，不重复增加后端模块。

- 问题：为什么设置页还保留很多面板？

​        解释：设置页是控制中心，保留配置、Harness、诊断、安全和验收能力。主工作台只聚焦 AI 对话和任务执行。
