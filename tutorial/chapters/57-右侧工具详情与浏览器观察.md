# 第五十七章. 右侧工具详情与浏览器观察

## 57.1 本章目标

​        学完本章后，你将能够：

​        具体来说，第一，理解为什么右侧工作区不应该再承担“工具历史列表”的职责；第二，把右侧工具工作区收敛为“当前工具调用详情”；第三，让中间对话流负责展示执行顺序，右侧工作区负责展示证据和细节；第四，让浏览器工具详情同时展示截图结果和 VNC 实时观察入口；第五，保留工具输出复制、参数查看和放大弹层；第六，理解文件预览、工具详情和上下文抽屉之间的互斥关系。这些点放在一起看，构成了本章叙述中需要连续理解的一条线索，而不是彼此孤立的项目清单。

## 57.3 本章要解决的问题

​        第 53 章已经把右侧做成了工具工作区，第 55、56 章又把中间区域收敛成 AI 对话叙事流。

​        但右侧仍然保留了一个问题：

```Plain
右侧既显示当前工具详情，又显示最近工具调用列表。
```

​        这会让页面出现两套执行顺序：

```Plain
中间对话流：一套任务执行顺序
右侧最近工具：另一套工具执行顺序
```

​        用户真正执行任务时，只需要在中间看到完整过程；当他对某个工具节点感兴趣时，再点击它，在右侧查看证据。

​        所以本章把页面职责重新收紧：

```Plain
中间：负责叙事和顺序
底部：负责输入和计划进度
右侧：负责当前工具或文件详情
```

​        这样页面更接近真实 Agent 产品的使用方式，也更容易继续维护。

## 57.5 实施步骤
### 57.5.1 确认右侧工作区的职责

​        本章不新增新的页面，也不新增新的演示入口。

​        先明确右侧工作区的职责：

```Plain
点击工具节点 -> 右侧显示该工具的完整详情
点击文件附件 -> 右侧显示该文件的内容预览
点击上下文按钮 -> 右侧显示上下文工程抽屉
```

​        这三种右侧内容互斥显示。

​        也就是说，右侧不会同时展示工具、文件和上下文，避免页面变成堆满面板的控制台。

### 57.5.2 让工具工作区只接收当前工具事件

​        打开 `ui/app/components/tool-preview-panel.tsx`。

​        本章先调整 `ToolPreviewPanel` 的核心逻辑：

```TypeScript
export function ToolPreviewPanel({
  events,
  onClose,
  onRefreshVnc,
  selectedToolEventId,
  vnc,
}: ToolPreviewPanelProps) {
  const [expandedEvent, setExpandedEvent] = useState<SessionEventItem | null>(
    null,
  );

  // ===================== 第1步：从事件列表中找出工具调用事件 =====================
  // 事件列表中既有 message_created、plan_created、step_started，
  // 也有 tool_called。右侧工具详情只关心 tool_called。
  const toolEvents = useMemo(() => getToolEvents(events), [events]);

  // ===================== 第2步：根据中间对话流点击的事件 ID 找到当前工具 =====================
  // selectedToolEventId 来自 ConversationTimeline 的工具节点点击事件。
  const selectedToolEvent =
    toolEvents.find((event) => event.id === selectedToolEventId) ?? null;

  // ===================== 第3步：准备标题和工具类型 =====================
  // 正常情况下，右侧只会在有 selectedToolEventId 时打开。
  // 这里保留一个 latest fallback，是为了防止极端状态下右侧出现空白。
  const activeToolEvent = selectedToolEvent ?? toolEvents[0] ?? null;
  const activeToolName = getString(activeToolEvent?.payload.tool_name);
  const activeToolKind = activeToolEvent
    ? getToolKind(activeToolName, getString(activeToolEvent.payload.output))
    : "Tool";

  return (
    <section className="flex h-full flex-col overflow-hidden border border-white/10 bg-[#08090d] shadow-2xl shadow-black/60">
      <div className="border-b border-white/10 bg-[#0b0d14]/95 p-5">
        <div className="flex items-start justify-between gap-3">
          <div>
            <div className="mb-2 text-xs font-medium uppercase tracking-[0.18em] text-zinc-600">
              Tool Detail
            </div>
            <h2 className="flex items-center gap-2 text-lg font-semibold text-zinc-50">
              <Monitor size={18} aria-hidden="true" />
              {activeToolName || "当前工具详情"}
            </h2>
            <div className="mt-2 flex flex-wrap items-center gap-2">
              <ToolKindBadge kind={activeToolKind} />
              <p className="text-sm leading-5 text-zinc-500">
                点击对话流里的工具节点后，在这里查看参数、输出和观察证据
              </p>
            </div>
          </div>
          <button
            aria-label="关闭工具详情"
            onClick={onClose}
            title="关闭工具详情"
            type="button"
          >
            <X size={17} aria-hidden="true" />
          </button>
        </div>
      </div>

      <div className="flex-1 overflow-auto bg-[#08090d] p-4">
        <ToolCallView
          events={events}
          onExpand={setExpandedEvent}
          onRefreshVnc={onRefreshVnc}
          toolEvent={activeToolEvent}
          vnc={vnc}
        />
      </div>
    </section>
  );
}
```

#### 57.5.2.1 代码讲解

​        这段代码做了三件事。

​        第一，仍然从 `events` 中提取 `tool_called`。因为后端所有工具调用最终都会落到事件表里，前端只需要统一消费事件。

​        第二，使用 `selectedToolEventId` 找到当前点击的工具。这个 ID 来自中间对话流，不来自右侧自己的列表。

​        第三，标题跟随当前工具变化。例如：

```Plain
browser_screenshot
search_web
shell_run
mcp_call
a2a_send_message
```

​        这样右侧不再像一个通用控制台，而是像当前工具的详情页。

### 57.5.3 删除右侧最近工具调用列表

​        继续修改 `ToolCallView`。

​        本章之后，`ToolCallView` 不再接收 `toolEvents`，只接收 `toolEvent`：

```TypeScript
function ToolCallView({
  events,
  onExpand,
  onRefreshVnc,
  toolEvent,
  vnc,
}: {
  events: LoadState<SessionEventItem[]>;
  onExpand: (event: SessionEventItem) => void;
  onRefreshVnc: () => void;
  toolEvent: SessionEventItem | null;
  vnc: LoadState<VncStatusData>;
}) {
  // ===================== 第1步：处理事件加载状态 =====================
  if (events.type === "loading") {
    return <EmptyState icon={RefreshCcw} text="正在读取工具事件..." />;
  }

  // ===================== 第2步：处理事件加载失败 =====================
  if (events.type === "error") {
    return <p className="text-sm text-rose-600">{events.message}</p>;
  }

  // ===================== 第3步：没有选中工具时给出轻量提示 =====================
  if (!toolEvent) {
    return <EmptyState icon={Bot} text="点击对话流里的工具节点查看详情。" />;
  }

  // ===================== 第4步：判断当前工具是否属于浏览器工具 =====================
  // 浏览器工具需要额外展示 VNC 远程桌面，Shell/Search/MCP 等工具不需要。
  const toolName = getString(toolEvent.payload.tool_name);
  const isBrowserTool = toolName.startsWith("browser_");

  return (
    <div className="grid gap-4">
      <ToolCallDetail event={toolEvent} onExpand={onExpand} />

      {isBrowserTool ? (
        <div className="grid gap-3">
          <div className="rounded-[22px] border border-blue-500/20 bg-blue-500/[0.06] px-4 py-3">
            <div className="flex items-center gap-2 text-sm font-semibold text-blue-100">
              <Monitor size={16} aria-hidden="true" />
              浏览器实时观察
            </div>
            <p className="mt-1 text-xs leading-5 text-blue-100/60">
              截图是工具调用的结果，远程桌面用于持续观察 Sandbox 中的浏览器画面。
            </p>
          </div>
          <VncPanel onRefresh={onRefreshVnc} state={vnc} />
        </div>
      ) : null}
    </div>
  );
}
```

#### 57.5.3.1 代码讲解

​        这一步删除了原来的“最近工具调用”区域。

​        删除它的原因不是功能少了，而是职责更清楚了：

```Plain
中间对话流已经是完整执行历史
右侧不需要再做第二个历史列表
```

​        如果要看前一个工具，只需要回到中间对话流，点击前一个工具节点。

​        浏览器工具仍然保留 VNC，因为它是“观察浏览器”的证据。其他工具不显示 VNC，避免无关信息干扰。

## 57.6 关键理解

​        本章最重要的是理解前端产品分工。

```Plain
中间对话流：展示任务过程
底部计划条：展示当前进度
右侧详情区：展示当前证据
```

​        右侧如果继续展示最近工具列表，会和中间对话流抢职责。页面看起来功能很多，但用户会不知道该从哪里读执行过程。

​        所以本章不是“删功能”，而是把功能放回正确位置。

​        第二个重点是浏览器工具的证据结构。

```Plain
browser_screenshot 输出一张截图
VNC 展示实时浏览器画面
```

​        截图适合记录某次工具调用的结果。

​        VNC 适合观察浏览器当前状态。

​        两者一起出现，用户才能理解浏览器工具到底做了什么。

## 57.8 常见问题

- 问题：右侧没有出现工具详情怎么办？

​        解释：先确认中间对话流里是否已经出现工具节点。右侧详情是点击工具节点后打开的，不再默认常驻展示最近工具。

- 问题：为什么删掉“最近工具调用”？

​        解释：工具调用顺序已经在中间对话流里展示。右侧继续展示列表会制造重复阅读路径，所以本章把右侧收敛为当前详情。

- 问题：为什么只有浏览器工具显示 VNC？

​        解释：VNC 是浏览器运行画面的观察窗口。Shell、搜索、MCP、A2A 等工具没有浏览器画面，不需要显示 VNC。

- 问题：点击文件后右侧显示文件，不显示工具，这是正常的吗？

​        解释：正常。右侧一次只显示一种详情：工具、文件或上下文。点击文件时会关闭工具详情，避免多个抽屉互相堆叠。

- 问题：构建 API 或 Sandbox 时，访问 `ghcr.io/astral-sh/uv` 超时怎么办？

​        解释：旧 Dockerfile 会通过 `COPY --from=ghcr.io/astral-sh/uv:0.11.15` 获取 `uv`，网络到 GHCR 不稳定时会在加载镜像元数据阶段失败。本章后的 API 和 Sandbox Dockerfile 改为从 Python 包源安装 `uv==0.11.15`，不再依赖 GHCR。

 还要注意，`uv.lock` 中可能记录 `files.pythonhosted.org` 的包文件直链，单纯设置 `UV_DEFAULT_INDEX` 不一定能避开这些直链。本章后的 Dockerfile 会先用 `uv export` 从锁文件导出普通 `requirements.txt`，再用 `uv pip install --default-index` 通过指定镜像源安装依赖。重新执行 `docker compose build api sandbox` 即可。如果当前镜像源也慢，可以临时切换：

```Bash
docker compose build \
  --build-arg PYTHON_PACKAGE_INDEX=https://mirrors.aliyun.com/pypi/simple \
  api sandbox
```
