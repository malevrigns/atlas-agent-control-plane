# 第三十八章. AI 对话工作台再造

## 38.1 本章目标

​        学完本章后，你将能够：

​        具体来说，第一，理解 AI Agent 产品里的“可观察执行轨迹”是什么；第二，区分可展示的执行过程和模型隐藏推理；第三，把用户消息、计划、步骤状态和工具调用合并成对话时间线；第四，在中间对话流里展示多 Agent 协作结果；第五，点击工具调用卡片后，让右侧工具预览自动切到对应工具；第六，删除旧的消息列表和事件记录演示组件。这些点放在一起看，构成了本章叙述中需要连续理解的一条线索，而不是彼此孤立的项目清单。

## 38.2 重要说明：这里不是展示隐藏思维链

​        真实产品里经常会看到：

```Plain
正在分析任务
正在生成计划
正在调用浏览器
正在查看工具结果
正在汇总答案
```

​        这些是“可观察执行轨迹”，不是模型内部隐藏 Chain-of-Thought。

​        本项目会展示：

​        换句话说，第一，用户消息；第二，AI 生成的计划；第三，步骤开始和完成状态；第四，工具调用参数和输出摘要；第五，多 Agent 的子任务、执行结果和评审状态；第六，任务完成或失败状态。这些点放在一起看，构成了本章叙述中需要连续理解的一条线索，而不是彼此孤立的项目清单。

​        本项目不会展示模型内部未公开的隐藏推理原文。

​        这一点很重要，因为产品需要让用户理解 Agent 在做什么，但不能把模型内部隐私推理直接暴露出来。

## 38.4 本章要解决的问题

​        第 37 章之前，页面中间主要展示消息，右侧展示计划、工具和事件。

​        问题是：用户真正关注的是一条完整对话里发生了什么。

​        如果把内容拆得太散：

```Plain
中间：只看消息
右侧：看计划
右侧另一个区域：看工具
右侧另一个区域：看事件
```

​        用户就很难建立因果关系：

```Plain
哪条消息触发了哪个计划？
哪个计划步骤调用了哪个工具？
哪个工具结果导致步骤完成？
多 Agent 协作结果在哪里？
```

​        本章把这些内容合并成中间的对话执行时间线。

​        右侧工具预览不再负责“告诉用户发生了什么”，而是负责“展示被选中工具的详细内容”。

### 38.7.2 把消息和事件合成时间线

​        `ConversationTimeline` 的核心是把两类数据合在一起：

```Plain
session_messages
session_events
```

​        代码如下：

```TypeScript
function buildTimelineItems(
  messages: ChatMessage[],
  events: SessionEventItem[],
): TimelineItem[] {
  const visibleEvents = events.filter((event) =>
    [
      "plan_created",
      "step_started",
      "tool_called",
      "step_completed",
      "task_done",
      "task_error",
    ].includes(event.type),
  );

  return [
    ...messages.map((message) => ({
      kind: "message" as const,
      id: `message-${message.id}`,
      created_at: message.created_at,
      message,
    })),
    ...visibleEvents.map((event) => ({
      kind: "event" as const,
      id: `event-${event.id}`,
      created_at: event.created_at,
      event,
    })),
  ].sort((left, right) => left.created_at.localeCompare(right.created_at));
}
```

#### 38.7.2.1 代码讲解

​        这里没有展示 `message_created` 事件。

​        原因是用户消息已经在 `messages` 里展示了。如果同时展示 `message_created`，页面会重复出现一条“消息已创建”事件，用户体验会很啰嗦。

​        真正进入对话执行流的是这些事件：

​        具体来说，第一，`plan_created`：AI 生成计划；第二，`step_started`：某个步骤开始；第三，`tool_called`：某个工具被调用；第四，`step_completed`：某个步骤完成；第五，`task_done`：任务完成；第六，`task_error`：任务失败。这些点放在一起看，构成了本章叙述中需要连续理解的一条线索，而不是彼此孤立的项目清单。

function getEventMeta(type: string) {
  if (type === "step_started") {
    return {
      className: "border-sky-200 bg-sky-50 text-sky-700",
      icon: CircleDot,
      label: "开始执行步骤",
      tone: "running" as const,
    };
  }
  if (type === "step_completed") {
    return {
      className: "border-emerald-200 bg-emerald-50 text-emerald-700",
      icon: CheckCircle2,
      label: "步骤完成",
      tone: "success" as const,
    };
  }
  if (type === "task_error") {
    return {
      className: "border-rose-200 bg-rose-50 text-rose-700",
      icon: AlertCircle,
      label: "执行失败",
      tone: "error" as const,
    };
  }
  return {
    className: "border-slate-200 bg-white text-slate-700",
    icon: MessageSquare,
    label: type === "task_done" ? "任务完成" : type,
    tone: "assistant" as const,
  };
}

## 38.10 常见问题

- 问题：中间只看到用户消息，没有计划和工具调用怎么办？

​        解释：发送消息后还需要点击“生成”和“执行”。消息保存只会产生用户消息，计划和工具调用来自后续步骤。

- 问题：看不到多 Agent 内联结果怎么办？

​        解释：任务里需要包含“多个 Agent”“分工”“协作”“评审”等关键词，让执行器命中 `multi_agent_collaborate`。

- 问题：右侧工具预览没有切换怎么办？

​        解释：确认点击的是中间的工具调用卡片，不是计划卡片或步骤状态卡片。

- 问题：为什么还保留右侧计划面板？

​        解释：右侧计划面板现在仍然承担“生成计划”和“执行计划”的控制入口。第 39 章之后会继续优化右侧预览和控制区。
