## 60.3 本章要解决的问题

​        第 59 章已经把主流程收敛成：

```Plain
发送任务 -> 自动规划 -> 自动执行 -> SSE 推送事件
```

​        但还有一个产品体验问题：后端为了保证工具结果可解析，会把很多工具输出保存成 JSON 字符串。

​        例如搜索工具返回：

```JSON
{
  "kind": "search_results",
  "provider": "bing-page",
  "query": "AI Agent latest news",
  "items": []
}
```

​        这对程序很好，对用户很糟。

​        用户真正想看到的是：

```Plain

```

​        所以本章在前端新增一层 `ToolObservation`，专门把工具原始输出转换成可读摘要。

## 60.6 实施步骤
### 60.6.1 为工具观察结果定义类型

​        打开 `ui/app/components/conversation/types.ts`，新增：

```TypeScript
export type ToolObservation = {
  title: string;
  brief: string;
  pills: string[];
};
```

#### 60.6.1.1 字段含义

​        从实现顺序看，第一，`title`：工具动作的短标题，例如“搜索完成”“浏览器截图完成”；第二，`brief`：给主步骤卡片显示的一句话摘要；第三，`pills`：步骤下方的轻量节点，例如搜索结果标题、查看截图、查看终端输出。这些点放在一起看，构成了本章叙述中需要连续理解的一条线索，而不是彼此孤立的项目清单。

#### 60.6.1.2 为什么这样设计

​        主对话流需要的是“任务过程”，不是“接口响应”。

​        `ToolObservation` 把这两者隔开：

```Plain
工具原始输出 -> ToolObservation -> 步骤卡片
```

​        这样工具输出再复杂，也不会直接污染中间对话流。

### 60.6.2 把工具输出转成观察摘要

​        打开 `ui/app/components/conversation/view-model.ts`，新增 `buildToolObservation()`。

​        完整函数如下：

```TypeScript
export function buildToolObservation(step: StepView): ToolObservation {
  const toolEvent = step.toolEvent;
  const toolName = getString(toolEvent?.payload.tool_name);
  const output = getString(toolEvent?.payload.output);

  if (!toolEvent) {
    return {
      title: "等待工具调用",
      brief: step.description || step.expected_output || "这个步骤还没有开始调用工具。",
      pills: [],
    };
  }

  const parsed = parseJsonObject(output);
  if (parsed?.kind === "search_results") {
    const query = getString(parsed.query);
    const items = Array.isArray(parsed.items) ? parsed.items : [];
    const titles = items
      .map((item) => getString((item as Record<string, unknown>).title))
      .filter(Boolean)
      .slice(0, 3);
    return {
      title: "搜索完成",
      brief: `已搜索“${query || step.title}”，找到 ${items.length} 条候选结果。`,
      pills: titles.length ? titles : ["查看搜索结果"],
    };
  }

  if (parsed?.kind === "browser_screenshot") {
    const size = Number(parsed.size || 0);
    const sizeKb = size > 0 ? `${Math.round(size / 1024)} KB` : "未知大小";
    return {
      title: "浏览器截图完成",
      brief: `已截取当前浏览器页面截图，图片大小约 ${sizeKb}。`,
      pills: ["查看截图", "打开远程桌面"],
    };
  }

  if (parsed?.kind === "mcp_tool_result") {
    const serverName = getString(parsed.server_name);
    const mcpToolName = getString(parsed.tool_name);
    return {
      title: "MCP 工具返回结果",
      brief: `已调用 ${serverName || "MCP Server"} 的 ${mcpToolName || "工具"}。`,
      pills: ["查看 MCP 输出"],
    };
  }

  if (parsed?.kind === "a2a_task_result") {
    const remoteAgent = getString(parsed.remote_agent);
    const status = getString(parsed.status);
    return {
      title: "远程 Agent 返回结果",
      brief: `${remoteAgent || "远程 Agent"} 已返回任务状态：${status || "unknown"}。`,
      pills: ["查看协作步骤", "查看远程输出"],
    };
  }

  if (parsed?.kind === "multi_agent_result") {
    const result = parseToolOutput(toolEvent);
    const subtasks = result?.subtasks.slice(0, 3).map((item) => item.title) ?? [];
    return {
      title: "多 Agent 协作完成",
      brief: result?.final_answer
        ? trimText(result.final_answer, 110)
        : `已完成 ${result?.subtasks.length ?? 0} 个子任务协作。`,
      pills: subtasks.length ? subtasks : ["查看协作结果"],
    };
  }

  if (toolName.startsWith("shell_")) {
    const returnCode = matchLineValue(output, "退出码");
    const command = matchLineValue(output, "命令");
    return {
      title: "Shell 命令执行完成",
      brief: `命令${command ? `“${command}”` : ""}已返回，退出码 ${returnCode || "未知"}。`,
      pills: ["查看终端输出"],
    };
  }

  if (toolName.startsWith("browser_")) {
    const pageTitle = matchLineValue(output, "页面标题");
    const currentUrl = matchLineValue(output, "页面已打开") || matchLineValue(output, "当前地址");
    return {
      title: "浏览器操作完成",
      brief: pageTitle
        ? `页面标题：${pageTitle}`
        : currentUrl
          ? `浏览器已打开：${currentUrl}`
          : "浏览器工具已返回结果。",
      pills: ["查看浏览器详情"],
    };
  }

  if (toolName.startsWith("file_")) {
    return {
      title: "文件工具完成",
      brief: firstUsefulLine(output) || "文件工具已返回结果。",
      pills: ["查看文件输出"],
    };
  }

  if (parsed) {
    return {
      title: "结构化工具结果",
      brief: "工具已返回结构化数据，点击右侧详情查看整理后的内容。",
      pills: ["查看工具详情"],
    };
  }

  return {
    title: getToolDisplayName(toolName),
    brief: firstUsefulLine(output) || "工具已返回结果。",
    pills: ["查看工具详情"],
  };
}
```

#### 60.6.2.1 这段代码在流程中的位置

​        调用链路是：

```Plain
SessionEventItem(tool_called)
  |
  v
StepView.toolEvent
  |
  v
buildToolObservation()
  |
  +-- StepCard
  +-- StepDetailDialog
```

#### 60.6.2.2 关键代码逐段解释

​        第一段处理“还没有工具事件”的情况。步骤还没执行时，页面应该显示步骤描述，而不是空白。

​        第二段处理 `search_results`。搜索工具返回的是结构化 JSON，但主对话里只展示搜索关键词、结果数量和前几个标题。

​        第三段处理 `browser_screenshot`。截图的 base64 很长，绝对不能进入步骤卡片。这里只显示截图大小和查看入口。

​        第四段处理 MCP、A2A、多 Agent。它们都是结构化协作结果，主对话只展示“谁完成了什么”，详细内容交给右侧详情。

​        第五段处理 Shell 和浏览器文本输出。它们不是 JSON，但有固定行格式，例如：

```Plain
命令：pwd
退出码：0
页面标题：Example Domain
```

​        所以这里用 `matchLineValue()` 提取关键行。

​        最后一段兜底。未知 JSON 不展示原文，只提示“结构化工具结果”。普通文本则取第一行作为摘要。

#### 60.6.2.3 小白最容易困惑的点

​        为什么不让后端直接返回前端摘要？

​        后端确实可以做，但工具事件本身需要保存完整证据。前端视图层负责“怎么展示给用户看”，后端负责“保存真实结果”。这两个职责分开，后续右侧详情才能继续查看完整工具输出。

### 60.6.3 为步骤卡片提供显示摘要

​        继续在 `view-model.ts` 中新增：

```TypeScript
export function getStepDisplaySummary(step: StepView) {
  if (step.status === "running") {
    return getRunningCopy(step);
  }
  if (step.status === "completed") {
    return buildToolObservation(step).brief || step.expected_output || "步骤已完成。";
  }
  if (step.status === "failed") {
    return "步骤执行失败，请查看任务错误或工具详情。";
  }
  return step.description || step.expected_output || "等待执行。";
}
```

#### 60.6.3.1 为什么这样设计

​        步骤卡片会遇到四种状态：

​        放到工程语境里看，第一，`pending`：还没执行，显示步骤描述；第二，`running`：正在执行，显示正在调用哪个工具；第三，`completed`：已完成，显示工具观察摘要；第四，`failed`：失败，显示可读错误提示。这些点放在一起看，构成了本章叙述中需要连续理解的一条线索，而不是彼此孤立的项目清单。

​        以前完成态会优先显示 `step.summary`，而 `step.summary` 来自后端 `step_completed.summary`。当前后端为了保留工具证据，会把原始工具输出放进去，所以前端必须在这里转成产品化文案。

### 60.6.4 让工具节点显示可读标签

​        继续更新 `buildToolPills()`：

```TypeScript
export function buildToolPills(
  step: StepView,
  output: MultiAgentInlineResult | null,
): string[] {
  const observation = buildToolObservation(step);
  if (observation.pills.length) {
    return observation.pills;
  }
  if (output?.subtasks.length) {
    return output.subtasks.slice(0, 3).map((subtask) => subtask.title);
  }
  return [
    `正在处理 ${step.title}`,
    step.expected_output || step.description || "整理任务结果",
  ];
}
```

## 60.7 关键理解

​        本章最重要的是理解三层数据：

```Plain
后端事件：真实记录，适合保存和调试
ViewModel：展示模型，适合组件消费
UI 组件：只负责渲染用户能理解的内容
```

​        不要让 UI 组件直接面对所有工具输出格式。

​        第二个重点是“思维链式步骤”不是模型私密推理。

​        本项目展示的是：

```Plain
任务步骤
工具动作
工具观察结果
完成状态
最终总结
```

​        不展示模型内部隐藏推理原文。

## 60.8 技术难点与亮点

​        技术难点：

​        展开来看，第一，不同工具输出格式差异很大，有 JSON，也有普通文本；第二，主对话流要可读，但右侧详情仍然要保留完整证据；第三，搜索结果、截图、Shell、MCP、A2A、多 Agent 都要走同一个步骤卡片模型。这些点放在一起看，构成了本章叙述中需要连续理解的一条线索，而不是彼此孤立的项目清单。

​        项目亮点：

​        具体来说，第一，新增 `ToolObservation`，把工具结果和 UI 展示解耦；第二，搜索、浏览器截图、多 Agent 等结构化结果不再污染主对话；第三，步骤卡片更像执行过程，而不是调试日志；第四，为第 61 章右侧详情抽屉打好数据边界。这些点放在一起看，构成了本章叙述中需要连续理解的一条线索，而不是彼此孤立的项目清单。

## 60.11 常见问题

- 问题：为什么后端还保存原始 JSON？

​        解释：原始 JSON 是工具证据，适合审计、调试和详情展示。主对话流只需要展示摘要。

- 问题：为什么不在后端直接生成中文摘要？

​        解释：后端负责保存事实，前端负责展示形态。这样右侧详情、步骤卡片和最终总结可以按不同场景消费同一份事件。

- 问题：为什么步骤详情弹层也不展示完整输出？

​        解释：步骤详情用于解释步骤本身。完整工具参数、输出、截图和 VNC 会在右侧工具详情抽屉展示。

- 问题：如果遇到新的工具类型怎么办？

​        解释：先在 `buildToolObservation()` 中增加一个分支，把它转成 `title`、`brief`、`pills`。组件不用改。
