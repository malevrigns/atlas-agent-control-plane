### 27.1.3 本节要解决的问题

​        前面的章节已经实现了会话消息、事件、上下文快照和上下文裁剪。

​        这些数据主要解决当前任务的执行问题，例如：

```Plain
用户刚才说了什么
当前计划有哪些步骤
已经调用了哪些工具
当前步骤执行到哪里
附件里有哪些文件
```

​        这些内容属于短期记忆。

​        但是跨会话工作时，还会遇到另一类信息：

```Plain
用户希望所有后端代码都保留详细分步注释
项目使用 FastAPI、Next.js、PostgreSQL 和 Redis
Docker 构建失败时应该先区分代码错误和镜像网络错误
不能把 API Key 写进代码或提交到 Git
```

​        这些信息即使换了一个新会话，仍然有价值，属于长期记忆。

​        如果每次新建会话都要求用户重新说明这些背景，Agent 的使用体验会很差。

​        如果直接把所有历史会话全部放进模型上下文，又会出现：

​        具体来说，第一，上下文越来越长；第二，Token 成本持续增加；第三，旧消息会干扰当前任务；第四，错误信息可能被长期放大；第五，模型难以找到真正相关的内容。这些点放在一起看，构成了本节叙述中需要连续理解的一条线索，而不是彼此孤立的项目清单。

​        所以本节建立独立的长期记忆系统。

### 27.1.4 短期记忆和长期记忆

​        先看两者的区别：

| 对比项   | 短期记忆                       | 长期记忆                               |
| -------- | ------------------------------ | -------------------------------------- |
| 使用范围 | 当前会话、当前任务             | 跨会话                                 |
| 典型内容 | 最近消息、计划、步骤、工具结果 | 用户偏好、项目事实、长期约束、历史经验 |
| 数据规模 | 随任务执行快速变化             | 数量较少、内容稳定                     |
| 生命周期 | 任务结束后价值可能降低         | 经过确认后长期保存                     |
| 使用方式 | 构建当前上下文快照             | 检索少量相关内容后注入上下文           |
| 风险     | 上下文过长                     | 错误记忆长期污染                       |

​        可以把它们理解成：

```Plain
短期记忆 = 当前工作台上正在使用的材料
长期记忆 = 经过整理后放进知识柜的稳定信息
```

​        长期记忆不是“永久保存全部聊天记录”。

​        它应该只保存跨会话仍然有价值的信息。

#### 27.1.7.1 定义长期记忆领域实体

​        创建：

```Plain
backend/api/app/domain/memories/entities.py
```

​        完整代码如下：

```Python
from dataclasses import dataclass, field
from datetime import datetime
from enum import StrEnum
from uuid import UUID

class MemoryKind(StrEnum):
    """长期记忆的业务分类。

    第 40 章先使用四类稳定分类：
    - user_preference：用户偏好，例如喜欢中文解释、希望代码多注释。
    - project_fact：项目事实，例如项目使用 FastAPI、Next.js、PostgreSQL。
    - task_experience：历史任务经验，例如某类任务应该先跑哪些验证。
    - constraint：长期约束，例如不要暴露密钥、不要提交某类文件。
    """

    user_preference = "user_preference"
    project_fact = "project_fact"
    task_experience = "task_experience"
    constraint = "constraint"

@dataclass(slots=True)
class AgentMemory:
    """跨会话保存的一条长期记忆。"""

    id: UUID
    kind: MemoryKind
    content: str
    importance: int
    enabled: bool
    source_session_id: UUID | None
    source_event_id: UUID | None
    expires_at: datetime | None
    metadata: dict[str, object] = field(default_factory=dict)
    created_at: datetime | None = None
    updated_at: datetime | None = None
    deleted_at: datetime | None = None

@dataclass(slots=True)
class MemoryCandidate:
    """从消息或事件中抽取出来、等待确认的记忆候选。"""

    kind: MemoryKind
    content: str
    importance: int
    reason: str
    source_session_id: UUID | None = None
    source_event_id: UUID | None = None
    metadata: dict[str, object] = field(default_factory=dict)
```

.1.7.1.1 代码讲解

​        `MemoryKind` 使用 `StrEnum`，数据库和 API 中保存的是稳定字符串。

​        四种分类分别解决：

​        从实现顺序看，第一，`user_preference`：用户希望系统如何回答或工作；第二，`project_fact`：项目本身长期稳定的背景信息；第三，`task_experience`：历史任务中总结出的执行经验；第四，`constraint`：后续任务必须遵守的限制。这些点放在一起看，构成了本节叙述中需要连续理解的一条线索，而不是彼此孤立的项目清单。

​        `AgentMemory` 是已经确认并写入数据库的正式记忆。

​        `MemoryCandidate` 只是候选，它比正式记忆多一个 `reason` 字段，用来解释为什么系统认为这段内容值得保存。

​        候选和正式记忆分开，可以避免下面的问题：

```Plain
普通聊天内容 -> 被误判为长期事实 -> 永久影响后续任务
```

.1.7.2.1 为什么要先定义协议

​        `MemoryService` 不应该知道数据库使用 SQLAlchemy、PostgreSQL 还是其他实现。

​        应用层只需要知道：

```Plain
可以新增记忆
可以按条件查询记忆
可以更新记忆
可以软删除记忆
```

​        这样本章后文增加向量检索或混合检索时，业务服务不需要直接改成数据库代码。

#### 27.1.7.3 创建 SQLAlchemy 模型

​        核心结构如下：

```Python
from datetime import datetime
from uuid import UUID, uuid4

from sqlalchemy import Boolean, DateTime, ForeignKey, Integer, String, Text, func, text
from sqlalchemy.dialects.postgresql import JSONB
from sqlalchemy.dialects.postgresql import UUID as PgUUID
from sqlalchemy.orm import Mapped, mapped_column

from app.domain.memories.entities import AgentMemory, MemoryKind
from app.infrastructure.database.base import Base

class AgentMemoryModel(Base):
    """长期记忆数据库模型。"""

    __tablename__ = "agent_memories"

    # ===================== 第1步：定义记忆主体字段 =====================
    id: Mapped[UUID] = mapped_column(
        PgUUID(as_uuid=True),
        primary_key=True,
        default=uuid4,
    )
    kind: Mapped[str] = mapped_column(String(64), nullable=False)
    content: Mapped[str] = mapped_column(Text, nullable=False)
    importance: Mapped[int] = mapped_column(Integer, nullable=False, default=3)
    enabled: Mapped[bool] = mapped_column(Boolean, nullable=False, default=True)

    # ===================== 第2步：保存记忆来源和生命周期 =====================
    source_session_id: Mapped[UUID | None] = mapped_column(
        PgUUID(as_uuid=True),
        ForeignKey("sessions.id", ondelete="SET NULL"),
    )
    source_event_id: Mapped[UUID | None] = mapped_column(
        PgUUID(as_uuid=True),
        ForeignKey("session_events.id", ondelete="SET NULL"),
    )
    expires_at: Mapped[datetime | None] = mapped_column(DateTime(timezone=True))
    metadata_json: Mapped[dict[str, object]] = mapped_column(
        "metadata",
        JSONB,
        nullable=False,
        default=dict,
        server_default=text("'{}'::jsonb"),
    )

    # ===================== 第3步：记录审计时间 =====================
    created_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True),
        nullable=False,
        server_default=func.now(),
    )
    updated_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True),
        nullable=False,
        server_default=func.now(),
        onupdate=func.now(),
    )
    deleted_at: Mapped[datetime | None] = mapped_column(DateTime(timezone=True))

    # ===================== 第4步：把 ORM 模型转换为领域实体 =====================
    def to_entity(self) -> AgentMemory:
        return AgentMemory(
            id=self.id,
            kind=MemoryKind(self.kind),
            content=self.content,
            importance=self.importance,
            enabled=self.enabled,
            source_session_id=self.source_session_id,
            source_event_id=self.source_event_id,
            expires_at=self.expires_at,
            metadata=dict(self.metadata_json or {}),
            created_at=self.created_at,
            updated_at=self.updated_at,
            deleted_at=self.deleted_at,
        )
```

.1.7.3.1 字段含义

​        放到工程语境里看，第一，`kind`：记忆业务分类；第二，`content`：记忆正文；第三，`importance`：重要度，范围为 1-5；第四，`enabled`：是否允许后续检索使用；第五，`source_session_id`：记忆来自哪个会话；第六，`source_event_id`：记忆来自哪个执行事件；第七，`expires_at`：可选过期时间；第八，`metadata`：抽取来源、规则和后续扩展信息；第九，`deleted_at`：软删除时间。这些点放在一起看，构成了本节叙述中需要连续理解的一条线索，而不是彼此孤立的项目清单。

.1.7.3.2 为什么来源外键使用`SET NULL`

​        如果来源会话被删除，不应该连带删除已经确认的长期记忆。

​        因此这里使用：

```Plain
ON DELETE SET NULL
```

​        删除来源后，只清空来源 ID，记忆正文仍然保留。

.1.7.3.3 为什么还需要`enabled` 和 `deleted_at`

​        两者用途不同：

```Plain
enabled=false：暂时不让 Agent 使用，但可以随时重新启用
deleted_at!=null：用户明确删除，普通查询不再返回
```

#### 27.1.7.5 实现长期记忆 Repository

​        Repository 负责：

```Plain
领域数据 <-> SQLAlchemy Model
```

​        新增记忆的核心代码：

```Python
async def add(
    self,
    *,
    kind: MemoryKind,
    content: str,
    importance: int,
    source_session_id: UUID | None,
    source_event_id: UUID | None,
    expires_at: datetime | None,
    metadata: dict[str, object],
) -> AgentMemory:
    # 1. 构建数据库模型，但不在 Repository 中提交事务。
    model = AgentMemoryModel(
        kind=kind.value,
        content=content,
        importance=importance,
        source_session_id=source_session_id,
        source_event_id=source_event_id,
        expires_at=expires_at,
        metadata_json=metadata,
    )
    self.db_session.add(model)

    # 2. flush 把 INSERT 发送给数据库，refresh 读取数据库生成字段。
    await self.db_session.flush()
    await self.db_session.refresh(model)

    # 3. 返回领域实体，不把 SQLAlchemy Model 暴露给应用层。
    return model.to_entity()
```

​        列表查询的核心代码：

```Python
async def list_active(
    self,
    *,
    kind: MemoryKind | None = None,
    enabled_only: bool = False,
    limit: int = 100,
) -> list[AgentMemory]:
    # 1. 默认过滤已经软删除的记录。
    stmt = select(AgentMemoryModel).where(
        AgentMemoryModel.deleted_at.is_(None)
    )

    # 2. 根据调用方参数增加过滤条件。
    if kind is not None:
        stmt = stmt.where(AgentMemoryModel.kind == kind.value)
    if enabled_only:
        stmt = stmt.where(AgentMemoryModel.enabled.is_(True))

    # 3. 重要度高、最近更新的记忆优先返回。
    stmt = stmt.order_by(
        AgentMemoryModel.importance.desc(),
        AgentMemoryModel.updated_at.desc(),
    ).limit(limit)

    result = await self.db_session.execute(stmt)
    return [model.to_entity() for model in result.scalars()]
```

.1.7.5.1 为什么 Repository 不执行`commit`

.1.7.7.1 手动创建记忆

```Python
# ===================== 第2步：手动新增长期记忆 =====================
async def create_memory(
    self,
    *,
    kind: MemoryKind,
    content: str,
    importance: int = 3,
    source_session_id: UUID | None = None,
    source_event_id: UUID | None = None,
    expires_at: datetime | None = None,
    metadata: dict[str, object] | None = None,
) -> AgentMemory:
    # 1. 清理并校验正文。
    clean_content = content.strip()
    if not clean_content:
        raise AppException(
            message="memory content is required",
            code=400,
            status_code=400,
        )

    # 2. 把重要度限制在 1-5。
    safe_importance = max(1, min(5, importance))

    # 3. 通过 Repository 写入当前数据库事务。
    memory = await self.uow.memories.add(
        kind=kind,
        content=clean_content,
        importance=safe_importance,
        source_session_id=source_session_id,
        source_event_id=source_event_id,
        expires_at=expires_at,
        metadata=metadata or {},
    )

    # 4. 由应用服务统一提交事务。
    await self.uow.commit()
    return memory
```

​        这里必须清理空白内容，因为长期记忆会在本章后文进入模型上下文。

.1.7.7.2 从会话抽取候选

```Python
# ===================== 第5步：从会话中抽取长期记忆候选 =====================
async def extract_candidates(
    self,
    session_id: UUID,
) -> list[MemoryCandidate]:
    # 1. 检查会话是否存在。
    session = await self.uow.sessions.get(session_id)
    if session is None:
        raise AppException(
            message="session not found",
            code=404,
            status_code=404,
        )

    # 2. 消息适合抽取用户偏好，事件适合抽取任务经验。
    messages = await self.uow.session_messages.list_by_session(session_id)
    events = await self.uow.session_events.list_by_session(session_id)

    # 3. 从消息正文中抽取候选。
    candidates: list[MemoryCandidate] = []
    for message in messages:
        candidates.extend(
            self._extract_from_text(
                text=message.content,
                source_session_id=session_id,
                source_event_id=None,
                source="message",
            )
        )

    # 4. 把事件 payload 转成文本，再抽取任务经验或项目事实。
    for event in events:
        text = " ".join(str(value) for value in event.payload.values())
        candidates.extend(
            self._extract_from_text(
                text=text,
                source_session_id=session_id,
                source_event_id=event.id,
                source=f"event:{event.type.value}",
            )
        )

    # 5. 去掉相同类型和相同正文的重复候选。
    return self._deduplicate_candidates(candidates)
```

### 27.1.8 关键理解

#### 27.1.8.1 长期记忆不是聊天记录备份

​        聊天记录记录“发生过什么”。

​        长期记忆保存“未来仍然值得使用什么”。

#### 27.1.8.2 记忆抽取和记忆写入是两个动作

```Plain
extract = 发现可能有价值的信息
create = 确认后正式保存
```

​        把两个动作分开，可以降低错误记忆污染。

#### 27.1.8.3 记忆必须可管理

​        长期记忆可能过时，也可能抽取错误。

​        因此必须提供：

```Plain
查看
禁用
重新启用
删除
来源追溯
过期时间
```

#### 27.1.8.4 本节还没有做检索

​        `GET /api/memories` 只是管理列表。

​        真正执行任务时，不能把所有记忆全部塞进上下文。

​        本章后文会根据：

```Plain
当前任务相关度
重要度
更新时间
过期状态
```

​        选出少量相关记忆。

### 27.1.9 技术难点与亮点

​        技术难点：

​        换句话说，第一，区分短期上下文和跨会话长期记忆；第二，避免把普通聊天内容自动保存成永久事实；第三，保留来源会话和来源事件，支持记忆追溯；第四，同时支持禁用、过期和软删除三种生命周期状态；第五，让领域层不直接依赖 SQLAlchemy。这些点放在一起看，构成了本节叙述中需要连续理解的一条线索，而不是彼此孤立的项目清单。

​        项目亮点：

​        从实现顺序看，第一，长期记忆不是简单消息复制，而是独立领域模型；第二，候选确认机制降低错误记忆污染风险；第三，记忆类型、重要度和来源为本章后文混合检索打基础；第四，前端管理入口进入设置页，不干扰真实对话工作台。这些点放在一起看，构成了本节叙述中需要连续理解的一条线索，而不是彼此孤立的项目清单。

.2.6.1.1 字段含义

.2.6.1.2 为什么要分候选数量和最终数量

​        候选数量解决“从哪里找”的问题。

​        最终数量解决“给模型看多少”的问题。

​        比如数据库里有 100 条记忆，当前任务真正需要的可能只有 3 条。如果直接把 100 条全塞进上下文，模型会被噪音淹没。

```Python
    # ===================== 第8步：读取可参与检索的长期记忆 =====================
    async def list_retrievable(
        self,
        *,
        now: datetime,
        limit: int,
    ) -> list[AgentMemory]:
        stmt = (
            select(AgentMemoryModel)
            .where(
                AgentMemoryModel.deleted_at.is_(None),
                AgentMemoryModel.enabled.is_(True),
                or_(
                    AgentMemoryModel.expires_at.is_(None),
                    AgentMemoryModel.expires_at > now,
                ),
            )
            .order_by(
                AgentMemoryModel.importance.desc(),
                AgentMemoryModel.updated_at.desc(),
            )
            .limit(limit)
        )
        result = await self.db_session.execute(stmt)
        return [model.to_entity() for model in result.scalars()]
```

.2.6.3.1 这段代码的业务流程

​        数据库先过滤三类不能用的记忆：

```Plain
已软删除 deleted_at != null
已禁用 enabled = false
已过期 expires_at <= now
```

​        然后按：

```Plain
重要度高
更新时间新
```

​        取一批候选。

​        最终相关度排序不在 Repository 做，而是在 `MemoryRetrievalService` 做。

.2.6.3.2 为什么不在 SQL 里算相关度

​        本节使用的是轻量关键词相关度，后续可能替换成：

​        换句话说，第一，PostgreSQL 全文检索；第二，embedding 向量相似度；第三，LLM rerank。这些点放在一起看，构成了本节叙述中需要连续理解的一条线索，而不是彼此孤立的项目清单。

​        把检索策略放在应用服务中，后续替换会更容易。

#### 27.2.6.4 实现 MemoryRetrievalService

​        创建：

```Plain
backend/api/app/application/memory_retrieval_service.py
```

​        完整代码如下：

```Python
import math
import re
from datetime import UTC, datetime

from app.application.unit_of_work import UnitOfWork
from app.core.config import settings
from app.domain.context_engineering.entities import MemoryContext, MemoryContextItem
from app.domain.memories.entities import AgentMemory, MemoryKind

class MemoryRetrievalService:
    """把长期记忆候选压缩成适合当前任务的 MemoryContext。

    第 41 章使用可解释的混合评分：
    - 相关度：当前任务和记忆正文匹配了多少关键词。
    - 重要度：第 40 章保存的 1-5 级重要度。
    - 新鲜度：最近更新的记忆获得少量加分。

    第 43 章可以在不改变 MemoryContext 结构的情况下，把相关度部分
    替换成 embedding、全文检索或模型重排。
    """

    def __init__(self, uow: UnitOfWork) -> None:
        self.uow = uow

    # ===================== 第1步：检索并压缩长期记忆 =====================
    async def retrieve(
        self,
        *,
        query: str,
        limit: int | None = None,
        max_chars: int | None = None,
        max_item_chars: int | None = None,
        now: datetime | None = None,
    ) -> MemoryContext:
        """根据当前任务返回少量可注入上下文的长期记忆。"""

        # 1. 统一检索参数。显式参数主要供测试使用，运行时读取全局配置。
        current_time = now or datetime.now(UTC)
        item_limit = limit or settings.context_memory_limit
        total_char_limit = max_chars or settings.context_memory_max_chars
        item_char_limit = max_item_chars or settings.context_memory_item_max_chars

        # 2. 先让数据库过滤禁用、删除和过期记录。
        candidates = await self.uow.memories.list_retrievable(
            now=current_time,
            limit=settings.context_memory_candidate_limit,
        )

        # 3. 计算混合分数，并过滤完全不相关的普通记忆。
        ranked_items = []
        for memory in candidates:
            item = self._rank_memory(
                memory=memory,
                query=query,
                now=current_time,
            )
            if item.relevance_score < settings.context_memory_min_score:
                continue

            # 普通项目事实和任务经验必须与当前任务有关键词交集。
            # 用户偏好和长期约束属于全局记忆，可以在无直接命中时保留。
            is_global_memory = item.kind in {
                MemoryKind.user_preference,
                MemoryKind.constraint,
            }
            if not item.matched_terms and not is_global_memory:
                continue
            ranked_items.append(item)
        ranked_items.sort(
            key=lambda item: (
                item.relevance_score,
                item.importance,
                item.updated_at or datetime.min.replace(tzinfo=UTC),
            ),
            reverse=True,
        )

        # 4. 同时应用“条数预算”和“字符预算”。
        included: list[MemoryContextItem] = []
        used_chars = 0
        for item in ranked_items:
            if len(included) >= item_limit:
                break

            remaining_chars = total_char_limit - used_chars
            if remaining_chars <= 0:
                break

            allowed_chars = min(item_char_limit, remaining_chars)
            compressed = self._compress_item(item, allowed_chars)
            if not compressed.content:
                continue

            included.append(compressed)
            used_chars += len(compressed.content)

        return MemoryContext(
            query=" ".join(query.split())[:1000],
            items=included,
            candidate_count=len(candidates),
            omitted_count=max(len(candidates) - len(included), 0),
            total_chars=used_chars,
            max_chars=total_char_limit,
        )

    # ===================== 第2步：计算单条记忆的混合分数 =====================
    def _rank_memory(
        self,
        *,
        memory: AgentMemory,
        query: str,
        now: datetime,
    ) -> MemoryContextItem:
        query_terms = self._tokenize(query)
        memory_terms = self._tokenize(memory.content)
        matched_terms = sorted(
            query_terms & memory_terms,
            key=lambda value: (-len(value), value),
        )[:12]

        # 1. 关键词重叠形成主要相关度。较长关键词权重略高。
        query_weight = min(
            sum(max(len(term), 1) for term in query_terms) or 1,
            40,
        )
        matched_weight = sum(max(len(term), 1) for term in matched_terms)
        lexical_score = min(matched_weight / query_weight, 1.0)

        # 2. 用户偏好和长期约束具有跨任务价值，即使没有直接命中关键词，
        #    也给一个很小的基础分，之后仍受数量和字符预算控制。
        global_memory_bonus = (
            0.04
            if memory.kind in {MemoryKind.user_preference, MemoryKind.constraint}
            else 0.0
        )

        # 3. importance 已经是 1-5，归一化到 0-1。
        importance_score = max(1, min(5, memory.importance)) / 5

        # 4. 新鲜度使用平滑衰减。越接近当前时间，分数越接近 1。
        updated_at = memory.updated_at or memory.created_at or now
        age_days = max((now - updated_at).total_seconds() / 86400, 0)
        recency_score = math.exp(-age_days / 90)

        final_score = min(
            lexical_score * 0.65
            + importance_score * 0.20
            + recency_score * 0.10
            + global_memory_bonus,
            1.0,
        )

        return MemoryContextItem(
            id=memory.id,
            kind=memory.kind,
            content=memory.content,
            importance=memory.importance,
            relevance_score=round(final_score, 4),
            matched_terms=matched_terms,
            original_chars=len(memory.content),
            truncated=False,
            source_session_id=memory.source_session_id,
            source_event_id=memory.source_event_id,
            updated_at=memory.updated_at,
        )

    # ===================== 第3步：按单条字符预算压缩记忆 =====================
    @staticmethod
    def _compress_item(
        item: MemoryContextItem,
        max_chars: int,
    ) -> MemoryContextItem:
        if max_chars <= 0:
            content = ""
        elif len(item.content) <= max_chars:
            content = item.content
        elif max_chars <= 12:
            content = item.content[:max_chars]
        else:
            content = item.content[: max_chars - 9] + "...[已裁剪]"

        return MemoryContextItem(
            id=item.id,
            kind=item.kind,
            content=content,
            importance=item.importance,
            relevance_score=item.relevance_score,
            matched_terms=item.matched_terms,
            original_chars=item.original_chars,
            truncated=len(content) < item.original_chars,
            source_session_id=item.source_session_id,
            source_event_id=item.source_event_id,
            updated_at=item.updated_at,
        )

    # ===================== 第4步：提取中英文检索词 =====================
    @staticmethod
    def _tokenize(text: str) -> set[str]:
        """提取英文单词和中文 2-4 字片段。

        这是第 41 章的轻量检索实现，不需要额外分词或向量依赖。
        """

        normalized = text.lower()
        terms = set(re.findall(r"[a-z0-9_]+", normalized))
        chinese_blocks = re.findall(r"[\u4e00-\u9fff]+", normalized)
        for block in chinese_blocks:
            for size in (2, 3, 4):
                if len(block) < size:
                    continue
                terms.update(
                    block[index : index + size]
                    for index in range(len(block) - size + 1)
                )
        return terms
```

.2.6.4.1 代码讲解

​        `retrieve()` 是入口方法。

​        它分 4 步完成：

1. 读取预算配置。
2. 从数据库拿候选记忆。
3. 给每条记忆打分并过滤。
4. 按条数和字符预算输出 `MemoryContext`。

​        `_rank_memory()` 是打分方法。

​        本节使用混合评分：

```Plain
最终分数 =
  关键词相关度 * 0.65
  + 重要度 * 0.20
  + 新鲜度 * 0.10
  + 全局记忆小加分
```

​        这里的权重不是“唯一正确答案”，而是一个可解释、可测试、适合课程阶段的起点。

.2.6.4.2 为什么用户偏好和长期约束可以无命中保留

​        有些记忆是全局规则，例如：

```Plain
用户希望代码保留详细注释
不要提交 API Key
```

​        它们不一定和当前任务有关键词重合，但仍然可能影响执行方式。

​        所以本节允许 `user_preference` 和 `constraint` 获得一个很小的基础分。

​        但项目事实和任务经验必须命中关键词，否则容易把无关项目背景带进当前任务。

```Python
@staticmethod
def _build_memory_query(
    *,
    task: str | None,
    session_title: str,
    messages: list[SessionMessage],
) -> str:
    """把当前任务、会话标题和最近消息合并为检索文本。"""

    parts = [task or "", session_title]
    parts.extend(message.content for message in messages[-3:])
    return "\n".join(part.strip() for part in parts if part.strip())
```

​        新增 Agent 提示词渲染方法：

```Python
@staticmethod
def render_for_agent(snapshot: SessionContextSnapshot) -> str:
    """生成 Planner 和 ReAct 可以直接使用的紧凑上下文文本。"""

    sections: list[str] = []

    if snapshot.memory_context.items:
        memory_lines = [
            (
                f"- [{item.kind.value}] {item.content} "
                f"(重要度 {item.importance}，相关度 {item.relevance_score:.2f})"
            )
            for item in snapshot.memory_context.items
        ]
        sections.append("长期记忆：\n" + "\n".join(memory_lines))

    if snapshot.messages:
        message_lines = [
            f"- {message.role}: {message.content}"
            for message in snapshot.messages
        ]
        sections.append("最近消息：\n" + "\n".join(message_lines))

    if snapshot.files:
        file_lines = [
            f"- {file.name} ({file.content_type}, {file.usage_hint})"
            for file in snapshot.files
        ]
        sections.append("文件引用：\n" + "\n".join(file_lines))

    return "\n\n".join(sections)
```

```Plain

最近消息：用户刚才补充了哪些细节
```

```Plain

```

### 27.2.7 关键理解

​        本节最重要的是理解：

```Plain
长期记忆不是历史聊天记录的全文回放。
```

​        正确链路应该是：

```Plain
历史信息
  |
  v
抽取成稳定记忆
  |
  v
当前任务检索相关记忆
  |
  v
压缩成 MemoryContext
  |
  v
注入 Planner / ReAct / Runner
```

​        第二个重点是预算。

​        长期记忆必须和最近消息、事件摘要、文件引用共享模型上下文空间。如果长期记忆占得太多，当前任务的最新信息反而会被挤出去。

​        第三个重点是可解释性。

​        本节没有直接引入向量检索，而是先用关键词相关度、重要度、新鲜度做混合评分。这样读者可以清楚看到每条记忆为什么被选中。

### 27.2.8 技术难点与亮点

​        技术难点：

​        展开来看，第一，长期记忆既要跨会话复用，又不能无脑全量注入；第二，用户偏好、项目事实、任务经验、长期约束的召回策略不同；第三，上下文快照要同时兼容前端展示和 Agent 提示词；第四，Planner 和 ReAct 需要使用同一套上下文结果，避免执行链路前后不一致。这些点放在一起看，构成了本节叙述中需要连续理解的一条线索，而不是彼此孤立的项目清单。

​        项目亮点：

​        具体来说，第一，前文保存的长期记忆开始进入真实执行链路；第二，`MemoryContext` 同时服务后端 Agent 和前端解释面板；第三，检索策略可解释、可测试，后续可以平滑升级为 embedding 或 LLM rerank；第四，前端可以看到“本次注入了哪些记忆”，而不是只相信黑盒结果。这些点放在一起看，构成了本节叙述中需要连续理解的一条线索，而不是彼此孤立的项目清单。

### 27.2.9 面试考点

​        换句话说，第一，短期上下文和长期记忆分别解决什么问题？；第二，为什么不能把所有长期记忆都放进 prompt？；第三，相关度、重要度、新鲜度分别代表什么？；第四，用户偏好和项目事实为什么不能用完全相同的过滤策略？；第五，为什么 `MemoryContext` 应该放进统一上下文快照？；第六，记忆检索服务如何写单元测试，为什么不应该依赖真实数据库？。这些点放在一起看，构成了本节叙述中需要连续理解的一条线索，而不是彼此孤立的项目清单。
