# 第八章. 会话状态与任务收放

流一旦开始，会话就不是 idle。左侧要能看出谁在跑、谁被停、谁有未读。状态只有三个字面量：`idle`、`running`、`stopped`。不要在这一层发明 `paused`、`cancelling`。停就是停，续跑是另一条 `resume: true` 的 stream。

`updateStatus` 改 `status` 和 `updated_at`。stream 开头写成 running，结束写成 idle。用户点停止，走 `POST /api/sessions/:id/stop`，写成 stopped，前端同时 abort 正在读的 SSE。若只 abort 不改库，刷新之后这条会话会永远转圈。

![停住，是一种明确的状态](../assets/ch08-pause.jpg)

未读是给左侧红点用的。用户消息写入时 `unread_count + 1`；打开会话点已读，清零。不要用「最后一条是不是助手」来猜，用户可能在别的标签页看完了。

前端的 `sendingMessage` 是全局布尔。切换会话时如果不把它打回 false，新会话的输入框会假死——上一轮还在发。`selectSession` 必须清掉 sending、planning、executing，以及 liveAnswer 缓冲。

`resume` 为真时 stream 不再插入一条用户消息，避免把同一句「继续」存两遍。当前 TypeScript 控制平面的 resume 还只是直答外壳；从失败步骤续跑执行机，要等 Agent 循环迁完。现在先保证状态位和中止不会把 UI 卡死。

```ts
router.post("/:sessionId/stop", async (c) => {
  const session = await sessions.updateStatus(c.req.param("sessionId"), "stopped");
  return c.json(ok(session));
});
```

打开工作台，发一条消息，在回答中途点停止，左侧应变为 stopped，输入框重新可点。再点同一条会话，时间线里应留下已经落库的那半截，而不是空白。
