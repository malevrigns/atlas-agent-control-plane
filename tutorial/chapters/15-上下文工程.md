# 第十五章. 上下文工程

模型窗口有限。不能把会话里所有消息、所有事件、所有记忆一股脑塞进去。上下文是裁剪的结果，不是日志的复印件。

`GET /api/sessions/:id/context` 已经返回一份快照：最近若干条消息（截断到每条 1200 字）、最近事件的类型摘要、空的记忆列表，以及一份 budget 计数——纳入了多少、省略了多少。前端右侧「上下文」面板读的就是它。现在记忆始终为零，数字仍然有意义：它让你看见裁剪在发生。

![灯只照到正在读的那一格](../assets/ch15-context.jpg)

```ts
return {
  session_id: session.id,
  summary: session.title,
  messages: messages.slice(-8).map(...),
  event_summaries: events.slice(-20).map(...),
  files: [],
  memory_context: { query: session.title, items: [], ... },
  budget: {
    message_limit: 8,
    event_limit: 20,
    included_messages: Math.min(messages.length, 8),
    omitted_messages: Math.max(0, messages.length - 8),
    ...
  },
};
```

以后接执行机，喂给模型的是同一份快照的变体：最近两步全文，更早的步骤压成 digest，再早的只留标题。那是第 63 章的预算。这一章只要接口在、面板能开、数字会对。刷新页面上下文还在，是因为消息和事件已经在库里，不是因为前端缓存。
