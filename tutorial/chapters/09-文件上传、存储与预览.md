# 第九章. 文件上传、存储与预览

Agent 要读用户丢进来的 PDF、日志、截图。文件不要塞进 SQLite 的 BLOB：库会胀，预览会慢，Nginx 也无法直接 `alias` 出去。表里只记元数据，字节写在 `UPLOAD_DIR`。

两张表。`files` 是对象本身：原名、存盘名、类型、大小、路径。`session_files` 是会话和文件的多对多，带唯一约束，同一文件不要在同一会话里挂两遍。下载 URL 是算出来的 `/api/files/:id/download`，不存绝对网址，换网关端口才不会全表作废。

![纸袋：内容在里面，目录在外面](../assets/ch09-files.jpg)

`FileService.saveUpload` 先看体积，超过 `MAX_UPLOAD_SIZE` 回 413。磁盘文件名用 uuid 加原后缀，避免用户上传 `../../../etc/passwd.jpg` 这种玩笑。预览只读前 `maxFilePreviewSize` 字节，当文本解码，行数按换行粗算。解析失败不要 500，把 `parse_status` 标出来让前端显示「无法预览」。

```ts
await this.db.insert(files).values({
  id,
  originalName: file.name || storedName,
  storedName,
  contentType: file.type || "application/octet-stream",
  size: file.data.byteLength,
  storagePath,
  createdAt: stamp,
});
```

路由上，会话附件走 `POST /api/sessions/:id/files`，字段名 `upload`，multipart。Hono 的 `parseBody()` 可能给出 File 或数组，handler 里要收窄类型，不能假定一定有 `.arrayBuffer()`。删除附件只拆关联，不立刻删盘上的对象——别的会话可能还指着它。真要回收，以后用引用计数，不要这一章做。

前端创建会话后应把 `files` 水合进 `attachments`。只展示 `attachments`、不读 `files`，刷新就会出现「明明传过、输入框底下空了」。

Nginx 的 `/uploads/` 有 `auth_request`，不要把上传目录直接映射成公开静态站。开发期走 API 下载接口就够。
